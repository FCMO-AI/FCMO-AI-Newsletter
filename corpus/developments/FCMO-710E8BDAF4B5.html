Agents & Memory

GraphSkillAA uses addressable skill graphs and two-stage gates for targeted agent-skill updates

Evidence Acredible_unconfirmedImpact 5/10 · Notableactive

technical_report · development FCMO-710E8BDAF4B5 · verified 2026-10-08T05:14:52Z

Importance: 5/10 — Notable. Importance measures consequence if true, not evidence quality.
If replicated beyond these fixed benchmark splits, addressable graph edits with rollback could change the design of external-skill optimization across agent systems. The reported evidence is limited to three benchmark suites and does not yet show deployed or long-horizon effects, so this is notable method progress rather than a field-shifting result.

The September 2026 v2 arXiv paper introduces GraphSkillAA, which represents external skills as a graph of addressable applicability, execution and exclusion fields plus typed relations. A teacher compares successful and failed executions to propose local edits; an affected-case Local Gate and a whole-update-pool Big Gate accept or roll back changes. The authors report three-seed held-out mean hard accuracies of 81.5% on SearchQA, 66.7% on LiveMath and 91.2% on DocVQA with GPT-5.6-sol, and highest reported means across nine model–benchmark comparisons in a separate SkillOpt-protocol table. These are paper-reported results, not independently reproduced evidence; the paper limits its conclusions to the tested splits, moderate graphs and primarily single-turn tasks.

Why it matters: If independently reproduced, the method offers a concrete way to update external agent procedures at specific graph objects while checking regressions and rolling back failed edits. This could influence how persistent skill libraries are optimized. The current evidence covers three benchmark suites and author-run model APIs, so it does not establish improved long-horizon agents, deployment utility or general self-improvement.

Technical record

Mechanism
The paper encodes each external skill as graph nodes with separate applicability, execution and exclusion fields and typed prerequisite/enhancement edges. After a failed rollout, a teacher contrasts related successes and failures and routes a supported repair to the smallest implicated node field or relation. A Local Gate retests affected update examples; a Big Gate evaluates merged changes over the complete update pool. A gate rejects and rolls back edits without a positive net gain. Student and teacher model parameters remain frozen; only the skill graph changes.
Demonstrated result
The arXiv v2 paper and public repository expose the proposed graph representation, update protocol and fixed benchmark manifests. The paper specifies disjoint update and test sets and three seeds (42–44) for graph-optimization runs. The public README says raw benchmark files are not redistributed. Static repository release-contract tests assert fixed model/seeds, command settings and disjoint manifests; they do not make model requests or reproduce the reported scores.
Publisher claim
The authors report three-seed held-out mean hard accuracies of 81.5% (SearchQA), 66.7% (LiveMath) and 91.2% (DocVQA) for GPT-5.6-sol in the main protocol. In Table A, the preceding G0 + Trace/Usage setting scores 76.2%, 51.3% and 88.2%, so the reported GraphSkillAA differences are +5.3, +15.4 and +3.0 percentage points. In Table C, one-factor ablations report average drops of 8.3 points without structured attribution, 4.9 without the Local Gate and 1.3 without correct-case protection; the Big Gate contributes +1.5/+4.6/+1.2 points on the three GPT-5.6-sol benchmarks. Separately, a SkillOpt direct-chat comparison reports the highest mean in all nine combinations of three models and three benchmarks. Half-ranges over three seeds are not confidence intervals, these are author-reported results, and this review did not independently reproduce them.
Strongest baseline
For the main protocol, the paper compares no-skill, flat-skill, structured-graph and graph-plus-trace/usage settings. A separate direct-chat protocol compares Trace2Skill, TextGrad, GEPA and SkillOpt using released test IDs, original inputs, inference budgets and scorers; this is not the same experimental protocol as the main table.
Regime
Author-run API experiments on SearchQA open-domain question answering, LiveMathematicianBench mathematical reasoning and DocVQA document-image question answering. The main GPT-5.6-sol protocol uses 800/468/800 update examples and 200/117/200 held-out examples, three seeds and strict exact-match scoring for SearchQA/LiveMath; DocVQA counts only ANLS=1 as correct. Experiments run for three epochs, primarily on moderate skill graphs and single-turn tasks.
Implementation
Public research prototype and benchmark scripts are available at the authors’ GitHub repository. The README requires an OpenAI-compatible model API; raw benchmark files are not redistributed, though a preparation script downloads pinned official snapshots. The README states local verification does not execute model requests.
Compute / cost
The paper describes per-epoch student and teacher call accounting and says latency and monetary cost are separate run-level quantities, but aggregate request cost and latency were not present in the inspected results tables. Reproduction should record resolved API model versions, call counts, concurrency, latency and monetary cost.
Novelty
Uses one addressable skill graph for skill selection, failure attribution, targeted edits, dependency-aware retest scope and rollback, rather than optimizing an undifferentiated skill document. Its tested contribution is the combined workflow; the paper does not isolate every factor in a full factorial experiment.
Reproducibility
Paper provides seeds, split sizes, held-out separation, protocol and public code/manifest-verification tools. At the inspected repository revision, release tests check fixed model/seeds, command construction and update/test ID separation; the verifier does not run model requests. Raw benchmark data are downloaded separately and results depend on hosted model APIs. No independent reproduction or audit of reported run outputs was performed.

Evidence claims

  • DEMONSTRATED — GraphSkillAA represents external skills as addressable graph fields and typed relations, routes proposed repairs using contrasted successful and failed cases, and uses local and whole-update-pool gates to accept or roll back changes.
  • CLAIMED — The authors report GPT-5.6-sol three-seed held-out mean hard accuracies of 81.5% on SearchQA, 66.7% on LiveMath and 91.2% on DocVQA under the paper’s main protocol.
  • CLAIMED — In a separate SkillOpt direct-chat comparison, the authors report GraphSkillAA has the highest mean in all nine model–benchmark combinations.
  • INFERRED — The reported findings are bounded to the paper’s benchmark splits, model/API setup and primarily single-turn tasks; they do not establish real-world deployment value or general agent self-improvement.
  • CLAIMED — The authors report that, relative to the preceding G0 + Trace/Usage setting, GraphSkillAA improves GPT-5.6-sol mean hard accuracy by 5.3, 15.4 and 3.0 percentage points on SearchQA, LiveMath and DocVQA; one-factor ablations report average drops of 8.3 points without structured attribution, 4.9 without the Local Gate and 1.3 without correct-case protection.
  • DEMONSTRATED — At the inspected repository revision, the authors’ release-contract tests check fixed model/seeds, command construction and update/test manifest separation; these checks do not execute model requests or independently verify reported scores.

Limitations / contrary evidence

  • The authors explicitly limit conclusions to fixed released test IDs and their method-specific procedures; three-seed half-ranges are not confidence intervals, and strict-match metrics can reject aliases or partial answers.
  • The main evaluation uses moderate graphs that can largely be rendered in full and primarily single-turn tasks; thousands-skill libraries and long-horizon delayed credit remain untested.
  • The public repository README says raw benchmark files are not redistributed and model requests require API access; model behavior can change over time.
  • No independent reproduction, independent baseline implementation audit, or deployment evaluation was performed in this review.
  • The Big Gate optimizes aggregate hard accuracy on the update pool; this does not establish safety or subgroup-risk behavior for consequential deployments.
  • The paper’s separate baseline comparison follows a direct-chat protocol distinct from its main graph-optimization protocol; claims across the two should not be merged.
  • The author repository’s release-contract tests check fixed configuration, command construction and update/test manifest separation, but do not execute model requests or verify benchmark outcomes.

Open evidence gaps

  • open · missing_independent — No independent reproduction of the three benchmark results or direct-chat baseline comparisons was inspected. — next: Run at least one benchmark from the public implementation using fixed manifests, a recorded model/API version and independent scoring; retain raw request/run outputs and compare against the stated baselines.
  • open · missing_artifact — The inspected public README says raw benchmark files are not redistributed, and the paper reports latency and monetary cost separately at run level without aggregate costs in the inspected result tables. — next: Inspect the repository’s versioned run artifacts and data manifests; record per-seed inputs, model version, request counts, concurrency, latency and cost, noting any unavailable raw outputs.
  • open · other — The paper’s tested graphs are moderate in size and tasks are primarily single-turn; longer-horizon and deployment utility are not established. — next: Evaluate a fixed graph-editing protocol on a larger skill library and multi-step tasks with held-out distribution shifts and explicit regression constraints.
