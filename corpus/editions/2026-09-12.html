FCMO AI Newsletter — 2026-09-12

Executive read

Today’s strongest pattern is that better AI systems are increasingly being built by changing the interfaces around learning—not merely by making the base model larger.

DeepSeek-V4.1-Flash attacks serving cost by changing how persistent context is represented and where compute is spent between prefill and decode. EnvCraft argues that long-horizon agents learn more from persistent executable environments than from generic tool-call traces or verbose “skill” text. Code2Skill tests a complementary route: compile source code into compact procedural memory before the agent has accumulated its own trajectories. Ecdysis shows why self-improvement needs restraint: editing a shared harness after every failure can be worse than leaving it unchanged, while cross-task failure aggregation recovers and improves performance. ActSafeGuard moves a deterministic constraint transform inside robot-policy training rather than clipping actions after generation. GE-Act 2.0 scales world-action learning across 30,000 robot-data hours, but its cross-embodiment story still lacks the decisive matched control. GPU-CFR shows a systems version of the same principle: when computation topology is fixed, flattening and compiling that structure can matter more than the accelerator trick added afterward.

The common lesson is practical: explicit structure is becoming a capability multiplier. The useful question is no longer only “which model is smarter?” but “what state, constraints, procedures, execution graph, and failure evidence does the model get to interact with—and which of those are causally load-bearing?”

1. DeepSeek-V4.1-Flash: long-context serving is being redesigned around persistent-state cost

DeepSeek released a 552B-parameter multimodal MoE with a 40-layer causal encoder-decoder split into a 20-layer causal encoder and 20-layer decoder. The serving design activates roughly 8B parameters per token during prefill and 16B during decode, projects decoder global KV from the encoder’s final states, combines sparse-attention reuse with FP4 KV storage and bounded sliding-window replay, and reports 890 bytes of global KV per token—about one quarter of DeepSeek-V4-Flash.

That is potentially consequential for long-running agents, where persistent context can dominate serving economics. But “small KV” is not the same thing as “cheap end-to-end inference”: weights, routing, communication, local/replayed state, activation memory and kernels still contribute.

DeepSeek’s own benchmark tables provide an important negative control. V4.1-Flash beats V4-Pro on some code/math tests, but trails it materially on SimpleQA-Verified, MultiLoKo, MATH, MGSM and LongBench-V2. The same checkpoint also moves sharply when the agent scaffold changes: DeepSWE rises from 65.5 to 74.2 and Terminal-Bench 2.1 from 84.1 to 90.6 across published harnesses. That scaffold spread is larger than several model-to-model gaps.

So the real experiment is not “does the new model top a leaderboard?” It is whether the architecture reduces cost per successful long-context task at the same harness, token budget and hardware.

Primary sources:

  • https://www.deepseek.com/en/news/deepseek-v4-1-flash/
  • https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash

2. ActSafeGuard: hard robot constraints work better when the policy trains through the same guard it will face at deployment

ActSafeGuard inserts a deterministic ray-scaling constraint operator directly into flow-matching action generation and uses the same operator during training and inference.

The strongest evidence is a stop-gradient ablation. On a dynamic “place shoe” task with position and velocity constraints, keeping the safeguard active at inference but preventing gradients through the safety scale collapses task success from 98% to 3%, even though both variants maintain 100% step-level constraint satisfaction. On a simpler static cup-placement task, the same ablation moves only 97% to 95%.

That contrast matters. The value of differentiating through the safety boundary is real in the reported dynamic regime, but it is not universal.

The most important limitation is semantic: 100% encoded-constraint satisfaction is not 100% real-world safety. If the obstacle model is wrong, perception misses a hazard, or the supplied feasible set omits a dangerous contact, the guard can perfectly enforce the wrong thing. Physical ALOHA evidence is also tiny—five rollouts per method per task.

The next decisive test is therefore adversarial constraint misspecification, not another clean-room success table.

Primary source: https://arxiv.org/abs/2609.11697

3. Ecdysis: a failed agent run is evidence to investigate, not automatic permission to rewrite shared code

Ecdysis studies self-improving agent harnesses and produces one of today’s most useful negative controls.

Starting from the same strong human-optimized Life-Harness, serial per-failure “Self-Evolution” averages 46.67% held-out accuracy—worse than leaving the human harness unchanged at 51.67%. Aggregating failures across tasks before editing raises performance to 54.67%; adding the paper’s collaborative refinement stage reaches 59.33%.

The result suggests a simple operational law: shared runtime code should change only when multiple sufficiently independent failures point to the same underlying harness defect.

Cross-model transfer is encouraging—the harness evolved using Qwen3-8B is frozen and evaluated on larger Qwen models, MiniMax-M2.7 and Llama-3.1-8B—but the experiment is not a perfectly matched-compute comparison. The refinement/coding stages use stronger external models, and some latency cells regress badly. Llama-3.1-8B Airline, for example, is reported at 159.60 seconds under full Ecdysis versus 43.38 under serial Self-Evolution.

The clean follow-up is a fixed-budget comparison: equal modifier-model tokens, equal validation executions, equal acceptance opportunities, with previously passing tasks retained as regression tests.

Primary source: https://arxiv.org/abs/2609.11677

4. EnvCraft: executable state transitions appear more valuable than generic synthetic tool traces

EnvCraft synthesizes sandboxed Python workspaces with persistent state, dependency-aware workflows, initialized environments and deterministic final-state verifiers. Automated filtering retains 139 environments and 19,777 tasks from a larger generated pool.

On Qwen3-8B, Claw-specific training raises PinchBench from 12.94 to 24.85 and ClawEval from 44.06 to 55.42, while reducing reported PinchBench token use from about 13.69K to 8.84K per task.

The more informative control is data composition. Generic EnvCraft tool-use data moves PinchBench only 12.94→14.51 and ClawEval 44.06→45.80, while the stateful Claw distribution reaches the much larger gains above. A component ablation tells a similar story: adding built-in executable system tools raises PinchBench from 14.96 to 24.02; adding synthesized skill guidance after that reaches only 24.33.

That weakens the simple “more synthetic data” or “more skill text” explanation. The executable environment itself appears to carry much of the useful training signal.

Reproduction is not yet complete. The public snapshot documents 7,396 general tool-use records plus 991 workspace task bundles rather than the full 19,777-task paper corpus, and the trained checkpoint is still marked coming soon.

Primary sources:

  • https://arxiv.org/abs/2609.05576
  • https://github.com/zeng-yirong/EnvCraft

5. Code2Skill: source code can become procedural memory, but retrieval is not uniformly beneficial

Code2Skill mines procedural abstractions from 19,769 GitHub repositories, challenges those abstractions through source-hidden reconstruction, then uses source-aware LLM adjudication to filter the resulting skill bank.

The authors report 1,006,822 accepted source-level records. The public dataset exposes 750,748 purpose-level cards, 945,993 source-to-card edges and 3,600 recurring patterns.

Across nine model settings and eight benchmarks, protocol-matched skill access moves the unweighted macro-average from 42.90 to 47.90 and improves 57 of 72 cells. That is broad, but not uniform: 15 cells are lower or flat, including failures on BigCodeBench, LongCLI and AgentBench-OS.

A useful context ablation argues against brute-force prompt stuffing. At retrieval depth k=3, compact summaries reduce visible skill context from 6,352 to 707 characters—88.9% less text—while preserving or improving the reported result in the tested setting.

The major caveat is the word “verification.” Reconstruction plus LLM adjudication is a scalable consistency filter, not formal proof that the skill preserves the source program’s behavior. Provenance is also incomplete for parts of the released bank, and poisoned or vulnerable upstream code remains an obvious security test.

Primary sources:

  • https://arxiv.org/abs/2609.05571
  • https://github.com/ant-intl/Code2Skill

6. GE-Act 2.0: robot-data scaling is real in the reported curve, but cross-embodiment causality is still unisolated

GE-Act 2.0 trains a world-action system from scratch on manipulation data, combining a control-oriented autoencoder, a visual planner and inverse dynamics.

Across a 300→30,000 robot-hour co-training ladder, zero-shot OOD success rises from 17.1% to 44.1% on G1-OP and 13.4% to 31.1% on G2-90D. G2-90D contributes less than 2% of the mixture yet improves by 17.7 points, and skill-specific data coverage correlates strongly with OOD success.

Those are meaningful scaling results, but the interpretation needs discipline. The largest model still fails most OOD trials, and the experiment changes both data quantity and mixture coverage. There is no matched control holding G2 examples and total compute fixed while removing data from other embodiments.

The KASO ablation is cleaner: filtering imagined futures whose implied actions disagree with recorded behavior raises a reported four-object G2 pick result from 22.5% to 37.5%.

The critical next test is target-only versus target-plus-other-embodiment versus target-plus-action-free-video at identical target data and compute.

Primary sources:

  • https://arxiv.org/abs/2609.05588
  • https://ge-act-v2.github.io/

7. GPU-CFR: most of the “80×” story appears to come from compiling the workload, not from CUDA Graphs alone

GPU-CFR exploits a property of counterfactual-regret minimization that general-purpose frameworks usually ignore: for a fixed game, the numerical state changes every iteration but the dependency graph does not.

The paper reports 29.8–80.4× speedup over the fastest prior GPU CFR baseline on the same A100 and 14–258× over LiteEFG on the four largest games. But the decomposition is more useful than the headline.

On HUNL turn, the reported ladder is about 11.667 ms/iteration for the reference path, 0.619 ms for compiled eager static dataflow, and 0.397 ms with CUDA Graph replay. In that cell, flattening/precomputing the computation supplies roughly an 18.8× gain before graph replay; replay adds another ~1.56×.

The public artifact is now verified, which improves auditability—but it also reveals reproduction limits. Many implementation modules are shipped as CPython-3.9 binary extensions rather than inspectable Python source. The NoRegret baseline drivers and some reference-stage tooling are missing, and the README says the full convergence/time-to-threshold comparison has not been remeasured with the reduced package. CUDA graph and eager paths agree to atol=1e-9 in tested configurations, not bitwise; the paper also reports a small numerical trajectory split in 4/20 same-seed HUNL-river runs due to unordered GPU reductions.

The reusable systems hypothesis is narrower and more interesting than “use CUDA Graphs”: compile repeated fixed-topology computation first; then measure whether graph replay still matters.

Primary sources:

  • https://arxiv.org/abs/2609.11923
  • https://github.com/lbn187/GPU-CFR

8. Business and geopolitics: China sets national targets for AI-native software and agent deployment

China’s Ministry of Industry and Information Technology has set a 2028 target to extend AI tools and platforms across more than 20,000 major software enterprises, support 100 intelligent-transformation projects, create 100 agent-software exemplar applications, and incubate more than five high-quality open-source projects.

The plan covers AI-assisted software production, intelligent software products, agent software, services, infrastructure and the surrounding development environment. It also calls for software-engineering datasets, flexible compute services, standards, talent development, safety mechanisms and open-source infrastructure.

This is meaningful industrial policy because it tries to change the distribution layer around coding agents and software automation—not merely fund another foundation-model lab.

But the numbers are targets, not outcomes. “20,000 firms covered” can be satisfied by shallow deployment; “100 agent exemplars” does not tell us whether those systems complete useful tasks reliably or economically. The evidence to watch is firm-level defect rates, accepted-code throughput, time-to-resolution, actual compute support, open-source artifacts and independently inspectable agent deployments.

Also notable

OpenAI updated GPT-Rosalind on September 11 to move the specialized life-sciences model out of research preview and make it available globally to eligible organizations through trusted access, with published pricing scheduled for October 5. That is a distribution change, not a fresh capability breakthrough. Earlier first-party results show modest MedChemBench gains, low absolute GeneBench accuracy despite better token efficiency, and a stronger proprietary LabWorkBench result that remains difficult to audit independently.

The correct question is whether specialization improves verified scientific outcomes per dollar under the same tools, not whether one vendor benchmark moves.

Source: https://openai.com/index/introducing-new-capabilities-to-gpt-rosalind/

What to watch next

Four experiments would materially change confidence in today’s picture.

First, benchmark DeepSeek-V4.1-Flash against a quality-matched decoder-only model on identical 128K–512K agent traces, measuring task success, TTFT, decode latency, peak HBM, persistent cache, joules and dollars—not just KV bytes.

Second, stress ActSafeGuard with deliberately incomplete and slightly wrong constraints. A perfect guard around a wrong feasible set is not a safety victory.

Third, unify the emerging agent-memory results: compare persistent executable environments, source-derived procedural memory, trajectory-derived memory and plain documentation under identical visible-token and synthesis budgets. That would tell us whether consequences, procedures or accumulated experience carry the most transferable signal.

Fourth, test GPU-CFR’s mechanism outside games. If flattening a fixed dependency graph still produces large gains on a non-CFR iterative workload, the result becomes a broader systems pattern rather than a specialized solver optimization.

Across all four, the measurement principle is the same: separate the attractive headline from the mechanism that actually moved the outcome.
