# FCMO AI Newsletter native-language publication contract

Status: **native publication requirement**.

FCMO AI Newsletter is natively published in exactly three languages:

- English (`en`) — canonical semantic source;
- Latin American Spanish (`es-419`) — curated translation;
- Simplified Chinese (`zh-Hans`) — curated translation.

Browser extensions, operating-system translation, search-engine translation, or other external systems may translate the site independently. Those translations are outside the Newsletter publication contract and are not presented as FCMO-curated editions.

## Core rule

Localization is not runtime machine translation. English remains the authoritative record. Spanish and Simplified Chinese wording is committed to this repository as reviewable, source-controlled publication data in `localization/translations.json`.

For every canonical `FCMO-<12 HEX>` brief, the following reader-facing story fields are mandatory in both curated locales:

- `title`
- `summary`
- `why_it_matters`

The recurring reader interface also carries a committed bilingual vocabulary for navigation and high-value editorial labels. Deep structured evidence fields that are not yet part of this localization contract remain canonical English rather than receiving an unreviewed synthetic fallback. The schema can be extended deliberately when more fields are curated.

## Translation doctrine

Translate meaning, not English sentence order. A curated translation must preserve:

1. claim strength and authority level;
2. uncertainty, limitations, caveats, and conditional language;
3. all material numbers, model/version names, benchmarks, organizations, dates, and technical distinctions;
4. the separation between evidence quality, confidence, and potential importance;
5. protected technical terms when translating them would make the text less precise;
6. natural target-language prose rather than translated-English syntax.

Current Spanish and Chinese entries are **model-curated and source-controlled**. Their metadata intentionally says `human_reviewed: false`. They must not be described as human reviewed unless a qualified bilingual reviewer actually performs that review.

## Fail-closed completeness and freshness

Every translation entry is pinned to the exact canonical English `title + summary + why_it_matters` with `source_sha256`.

`tools/i18n_release.py` fails the release if:

- a canonical brief has no Spanish or Simplified-Chinese entry;
- any required translated field is empty;
- a translated field is unchanged canonical English;
- an orphan translation points to a non-existent brief;
- the canonical English core fields changed without the curated translations being revisited and their source hash refreshed;
- a runtime translation provider is introduced;
- the generated localized derivative differs from its deterministic source projection.

This means a new story cannot silently publish in English only, and an English edit cannot silently leave stale ES/ZH copy behind.

## Release ordering and integrity

The frozen Signal Field release remains the canonical release artifact and is verified **before** localization:

1. `tools/apply_final_release.py` reconstructs and validates the exact frozen canonical release and its hashes.
2. `tools/i18n_release.py` validates the committed translation catalogue against the canonical briefs.
3. The tool emits public `data/translations.json` and injects the deterministic language runtime into the already-validated HTML tree.
4. `localization-manifest.json` records the canonical release identity, source-catalogue hash, locale contract, page/brief counts, and a hash of the complete localized derivative.
5. A second validation pass verifies the derivative before Pages may upload it.

Localization therefore does not weaken or rewrite the frozen-release integrity check; it is a separately hashed deterministic derivative applied afterward.

## Locale resolution

The reader resolves language in this order:

1. explicit `?lang=` request;
2. saved manual language selection;
3. `navigator.languages` / browser preference;
4. English fallback.

Spanish-family locale tags resolve to `es-419` because that is the curated Spanish edition.

Simplified-Chinese tags (`zh`, `zh-Hans`, `zh-CN`, `zh-SG`, `zh-MY`) resolve to `zh-Hans`. Traditional-Chinese tags (`zh-Hant`, `zh-TW`, `zh-HK`, `zh-MO`) do **not** silently receive Simplified Chinese as though it were a curated Traditional-Chinese edition; they fall through to canonical English unless the reader explicitly selects 简体中文.

The language control exposes only:

- English
- Español
- 简体中文

No fourth native locale should be added without an explicit publication-contract change and its own curated catalogue.

## Runtime boundary

The browser localization runtime is deliberately small and deterministic. It:

- reads only the committed public translation catalogue;
- changes the document language and reader-facing copy;
- applies translations to dynamic search/index content through DOM observation;
- preserves the selected locale on internal static navigation;
- stores the reader's manual preference locally;
- never calls a translation API, LLM endpoint, or generative fallback.

Missing or stale curated copy is a release defect, not permission to synthesize text at runtime.

## Updating or adding a story

When a canonical story is added or its core English copy changes:

1. update the English brief normally;
2. curate `title`, `summary`, and `why_it_matters` in both `es-419` and `zh-Hans`;
3. preserve evidence level, numerical claims, caveats, and technical identities;
4. refresh the entry's `source_sha256` against the final canonical English core;
5. run the release validator;
6. inspect both target languages at desktop and compact viewport widths before considering the publication complete.

This follows the same core discipline used by `.CMPCT`: English canonical authority, committed locale packs, deterministic presentation, explicit fallbacks, and quality gates instead of runtime translation.
