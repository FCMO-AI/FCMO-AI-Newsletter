# FCMO AI Newsletter curated localization contract

Status: **native publication contract**.

FCMO AI Newsletter supports exactly three native publication languages:

- English (`en`) — canonical semantic source;
- Latin American Spanish (`es-419`) — curated translation;
- Simplified Chinese (`zh-Hans`) — curated translation.

Other browser extensions, operating-system translators, or external services may translate the site independently, but they are outside the Newsletter publication contract.

## Doctrine

Localization is **not runtime machine translation**. English remains the canonical record. Spanish and Simplified Chinese wording is committed to the repository as reviewable, source-controlled publication data and is applied deterministically in the reader.

Translate intent rather than English syntax. A translation must preserve:

1. the authority level of every claim and caveat;
2. all material numbers, model/version names, benchmarks, organizations, and protected technical terminology;
3. the distinction between evidence, confidence, and importance;
4. uncertainty, limitations, and conditional language without strengthening or weakening them;
5. natural target-language prose rather than translated-English sentence structure.

The initial native story contract covers the three editorial fields that define each news item wherever it appears: `title`, `summary`, and `why_it_matters`. Structured evidence/metadata remains canonical and language-stable unless a later schema revision explicitly adds a curated localized field.

Translations in the current catalogue are **model-curated and source-controlled**. They must not be described as human reviewed unless a qualified bilingual reviewer has actually reviewed the relevant locale.

## Completeness gate

Every development ID present in `site/data/developments.jsonl` must have both an `es-419` and a `zh-Hans` entry in `site/data/translations.json`, and each entry must contain non-empty translations for:

- `title`
- `summary`
- `why_it_matters`

The Pages build fails closed when this contract is incomplete. A new story therefore cannot silently arrive in English only.

## Locale resolution

The browser resolves a locale in this order:

1. explicit `?lang=` request;
2. the visitor's saved manual selection;
3. `navigator.languages` / browser preference;
4. English fallback.

Spanish family tags resolve to `es-419`. Simplified-Chinese tags (`zh`, `zh-Hans`, `zh-CN`, `zh-SG`, `zh-MY`) resolve to `zh-Hans`. Because the Newsletter currently publishes only curated Simplified Chinese, other Chinese script/region tags fall back to canonical English rather than pretending a Simplified-Chinese adaptation is a curated Traditional-Chinese edition.

The selector always exposes English as the canonical source and the two curated translations explicitly.

## Runtime boundary

`tools/i18n_site.py` operates only on the already-public static tree during GitHub Pages assembly. It:

- validates catalogue completeness against public development IDs;
- injects a self-contained deterministic language selector/runtime into generated HTML;
- applies committed story translations by exact canonical phrase matching;
- observes dynamically rendered content, including search results;
- updates the document language and preserves the selected locale in navigation;
- never calls a translation API, model endpoint, or remote asset.

Missing translation content is a release defect, not an invitation to synthesize a fallback.

## Updating a story

When canonical English `title`, `summary`, or `why_it_matters` changes:

1. update the English public record normally;
2. update both curated locale entries in `site/data/translations.json` in the same publication change;
3. preserve technical names, quantitative claims, qualifiers, and uncertainty;
4. run the public Pages validation;
5. inspect ES and ZH rendering at compact and desktop widths before treating the publication as complete.

This mirrors the `.CMPCT` localization discipline: committed locale packs, deterministic presentation, explicit canonical authority, and quality gates rather than runtime translation.
