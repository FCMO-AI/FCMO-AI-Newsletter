La reejecución contrafactual mejora la supervisión informada de recuperación robótica ante fallos ambiguos

MAGMA-GEN utiliza un coach privilegiado para sugerir correcciones localizadas o acciones de recuperación tras un fallo robótico ambiguo; después vuelve a ejecutar cada propuesta desde el mismo estado de simulación y la conserva solo si mejora el progreso posterior. En la evaluación simulada de manipulación, los autores informan en cuatro ejecuciones una tasa media de recuperación de 26.25% frente a 16.66% para la línea base Best-of-N más fuerte, y éxito de tarea completa de 16.79% frente a 14.15%. Con factor de ramificación B=2, informan 15/30 pruebas físicas exitosas, frente a 12/30 para destilación de trayectorias expertas y 11/30 para CLEANER-adapted; cada método usó un checkpoint, así que la pequeña prueba física no establece superioridad estadística. El artículo informa un mecanismo acotado y viabilidad de transferencia, no robótica robusta a largo plazo. El repositorio enlazado ahora es una beta v2, mientras el artículo describe el software v0.1; siguen abiertas la correspondencia exacta de versiones y la reproducción independiente.

Afirmación vs. evidencia

  • DEMONSTRATED_PUBLICATION_EVENT — Los autores publicaron arXiv:2609.20056v1 el 2026-09-17 con el título MAGMA-GEN: Validated Recovery Supervision from Ambiguous Failures via Counterfactual Re-Execution.
  • AFIRMADO — En la evaluación simulada informada, MAGMA-GEN (B=1) obtuvo una tasa media de recuperación de 26.25% frente a 16.66% para la línea base Best-of-N más fuerte, éxito acumulado de tareas de 16.79% frente a 14.15% y fracción de objetivos completados de 30.74% frente a 26.73%; son promedios de cuatro ejecuciones de generación sobre las mismas 180 instancias con semillas.
  • AFIRMADO — Con factor de ramificación B=2, los autores informan 38.35% de éxito acumulado simulado y 40.0% de recuperación, frente a 26.99% y 18.33% para la destilación de trayectorias expertas bajo el control de ramificación emparejado.
  • AFIRMADO — En un robot físico Franka Emika, el checkpoint B=2 tuvo éxito en 15/30 pruebas, frente a 12/30 con destilación de trayectorias expertas y 11/30 con CLEANER-adapted; el artículo señala que un checkpoint por método y 30 pruebas demuestran viabilidad de transferencia, no superioridad estadística.
  • NOT_ESTABLISHED — Este preprint no establece reproducción independiente, superioridad estadística en robots físicos, reproducción exacta del software v0.1 del artículo con el repositorio beta actual v2.0.0b2 ni transferencia más allá de esta batería de tareas.

Baseline más fuerte

La destilación de trayectorias expertas Best-of-N con llamadas 20B y hasta 10 reintentos por subobjetivo es la línea base B=1 más fuerte para recuperación (16.66%) y éxito de tareas completas (14.15%). Para ramificación y comparación física se usa un control emparejado de destilación de trayectorias expertas B=2.

La salvedad que importa

  • Los resultados los informan los autores; esta activación no ejecutó el código ni reprodujo de forma independiente las simulaciones o pruebas físicas.
  • Los resultados simulados usan una política de ejecución 4B y un coach privilegiado 20B para entrenar la misma política Qwen3-4B, ManiSkill3 y 279 tareas reservadas en cuatro escenarios con 3–18 acciones de alto nivel.
  • La comparación principal B=1 promedia cuatro ejecuciones de generación sobre 180 instancias con semillas; el éxito absoluto en tareas completas sigue siendo 16.79% y los errores se acumulan en horizontes largos.
  • La prueba física B=2 usa un único checkpoint por método y 30 pruebas; los autores indican que demuestra viabilidad de transferencia, no superioridad estadística.
  • La generación de datos requiere acceso privilegiado a estados de simulador restaurables y consecuencias de acción a nivel de tarea suficientemente fieles; las discrepancias y los reinicios costosos o imposibles pueden limitar el uso físico.
  • El artículo identifica el software v0.1, mientras que el README del repositorio enlazado describe v2.0.0b2 como beta con validación integral en curso; esta revisión no estableció equivalencia entre versiones.

Qué sigue sin saberse

  • No se identificó una reproducción independiente; el repositorio enlazado actualmente es la versión beta 2.0.0b2, mientras el artículo indica usar el software v0.1. No se inspeccionaron el código exacto de esa versión ni la correspondencia de artefactos.
  • La comparación física usa 30 pruebas y un checkpoint por método; los autores indican explícitamente que no establece superioridad estadística.
  • El método depende de estados de simulador privilegiados y restaurables, y de dinámicas de tareas suficientemente fieles para que las ramas validadas se transfieran; se desconoce su eficacia cuando no hay reinicio o aumenta la discrepancia de bajo nivel.

Lente FCMO

Los fallos robóticos suelen mezclar decisiones de alto nivel equivocadas con errores estocásticos de ejecución, por lo que etiquetar cada fallo como error de política puede perjudicar el entrenamiento. MAGMA-GEN prueba las correcciones propuestas desde el mismo estado de simulación y usa el progreso posterior observado para filtrar la supervisión. Si se reproduce de forma independiente, ofrece una vía práctica para entrenar recuperación a partir de los propios estados de fallo de una política. La evidencia actual proviene de una sola batería acotada, con bajo éxito absoluto de tarea completa, acceso privilegiado al estado del simulador y pocas pruebas con robot físico.
