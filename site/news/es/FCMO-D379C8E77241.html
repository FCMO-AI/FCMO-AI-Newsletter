R3Con informa grandes mejoras en dos pruebas de razonamiento sobre contextos extensos

Un preprint de septiembre de 2026 presenta R3Con, un sistema que extrae repetidamente el contexto pertinente para una tarea de grandes colecciones de documentos, construye una estructura flexible —por ejemplo, una tabla o un grafo— y después usa un agente de programación para razonar sobre ella. En CorpusQA y Loong, los autores informan mejoras de exactitud general de 19.88 y 8.42 puntos porcentuales, respectivamente, frente a las mejores líneas de base evaluadas. También informan que las configuraciones de R3Con con modelos 4B y 9B superaron todas las líneas de base 35B evaluadas, y que una ejecución con Qwen3.5-35B-A3B superó una comparación con Claude Code/Sonnet 5 a un costo reportado aproximadamente 3.7 veces menor. Son resultados de un solo artículo y dos pruebas; ambas usan evaluación de un modelo juez, y la comparación de costos entre sistemas no separa los efectos del modelo y del sistema.

Evidencia

  • Afirmado — En CorpusQA y Loong, los autores informan que R3Con mejoró la exactitud general en 19.88 y 8.42 puntos porcentuales, respectivamente, frente a la mejor línea de base evaluada en sus experimentos.
  • Afirmado — Los autores informan que las versiones de R3Con con Qwen3.5-4B en Loong y Qwen3.5-9B en CorpusQA superaron todas las líneas de base 35B evaluadas; su configuración Qwen3.5-35B-A3B también superó una comparación con Claude Code que usó Claude-Sonnet-5, con un costo reportado unas 3.7 veces menor.

Línea base más fuerte

La mejor línea de base informada es StructRAG en CorpusQA (50.76% general) y CodeAgent en Loong (29.01% general); R3Con informa 70.64% y 37.43%, respectivamente. El artículo también compara con Claude Code usando Claude-Sonnet-5, pero se trata de una comparación entre sistemas y no de una ablación con el mismo modelo y distinto sistema.

Limitaciones

  • La evaluación abarca dos pruebas y sus tareas seleccionadas; se desconoce la transferencia a otras colecciones, dominios o cargas de trabajo operativas.
  • Ambas pruebas usan una métrica evaluada por un modelo juez; en esta revisión no se confirmó una adjudicación humana o determinista independiente.
  • La comparación con Claude Code cambia el modelo y el sistema a la vez, por lo que no aísla el efecto de R3Con ni demuestra una ventaja general de costo y rendimiento.
  • El costo informado usa precios de API publicados, no mediciones independientes del cómputo integral, la latencia, el trabajo de ingeniería o la infraestructura.
  • En esta activación no se realizó una reproducción independiente ni una auditoría completa del código y los datos.

Lo que aún no sabemos

  • Las mejoras informadas en las pruebas y las comparaciones con modelos más pequeños no se han reproducido de forma independiente.
  • Las comparaciones por tamaño de modelo y con Claude Code no aíslan el efecto de la representación y del sistema con un mismo modelo, entorno de ejecución y contabilidad de costos.

Por qué importa

Si se replica en colecciones más amplias, una etapa que construya representaciones adaptadas a cada tarea podría mejorar la integración de evidencia de varios pasos y reducir el tamaño de modelo necesario en algunas tareas de contexto extenso. El artículo ofrece un diseño concreto y una comparación de pruebas para esa posibilidad. Los resultados se limitan a dos evaluaciones, líneas de base elegidas por los autores y puntuaciones de un modelo juez; la comparación de costos no es una ablación con el mismo sistema base.
