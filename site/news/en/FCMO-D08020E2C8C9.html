Evidence

  • Demonstrated — arXiv hosts a 24-page v1 preprint submitted on 2026-10-10 that studies capability-dependent effects of agent skills and skill adaptation.
  • Claimed — Across 607 tasks from SkillsBench, DocOps and Tessl, the authors select 103 skill-sensitive task-skill pairs and report that injected skills can substantially help stronger models while leaving weaker models nearly unchanged or harming them; 86% of failed weak-model runs on the selected pairs violate requirements already stated in the skill.
  • Claimed — In one-shot adaptation on the 103 selected pairs, the authors report that capable rewriters using their meta-skill improve the mean scores of three weaker executors; Kimi-K3 raises Gemma-4-E4B from 0.029 to 0.170, while the weak executors’ own rewrites score below the original-skill baseline on average.
  • Claimed — In a five-round self-evolution experiment, the meta-skill arm ends above the no-meta arm for all seven tested executors, with reported round-five differences of 0.020–0.051 in average task score.
  • Not established — The preprint does not establish repeat-run stability, independent reproduction, transfer to untested executors or benchmarks, benefits when skills must be retrieved, or effects from updating model parameters.
  • Demonstrated — The author project page links a public MIT-licensed reproduction repository containing benchmark task indexes, configuration and instructions for evaluation, skill adaptation and self-evolution. This activation inspected the repository page and README but did not execute its code.

Strongest baseline

For one-shot adaptation, original unrevised skills and a one-sentence rewriting prompt are comparison arms. For self-evolution, the authors compare the meta-skill loop with the same executor revising without the meta-skill and with a same-window baseline rerunning the original skill.

Limitations

  • The preprint’s benchmark results are author-reported and have not been independently reproduced here.
  • The 103 task-skill pairs are selected as skill-sensitive from an initial 607-task set; results on this selected subset do not represent all tasks.
  • Each model-task-condition cell is run once. The authors say exact effect sizes of the five-round comparison should not be overinterpreted.
  • The study evaluates skills already supplied to the executor; retrieval and progressive disclosure are outside scope. Some comparisons treat bundles of multiple skills as one pair.
  • A public author reproduction repository is now linked from the project page. This activation did not pin its commit, audit its code, run its tests or reproduce model outcomes; provider endpoints and benchmark environments can affect results.

What we still don't know

  • No independent reproduction or repeated-run variance estimate was inspected; the paper reports each model-task-condition cell once.
  • A public author reproduction repository is now available, with task indexes, source revision/checksum metadata and experiment commands. This activation did not pin a commit, audit code paths or run the repository; source-only tests would not reproduce model outcomes.
  • Skill retrieval and progressive disclosure are out of scope; tasks use skills already supplied in context, and multiple skills are sometimes evaluated as a bundle.

Why it matters

The paper makes a useful distinction between having relevant procedural guidance and an executor being able to act on it. If replicated, capability-matched skill wording and trajectory-based revision could change how agent harnesses are designed and evaluated. The study covers supplied skills and selected task pairs; it does not test skill retrieval or progressive disclosure, and its self-evolution runs are single rollout per cell.
