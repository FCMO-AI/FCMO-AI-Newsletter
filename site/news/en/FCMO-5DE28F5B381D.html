Evidence

  • Demonstrated — A research paper titled “MCP Tool Poisoning in Agentic AI Frameworks: A Cross-Framework Measurement Study” was posted to arXiv on 2026-11-02; the linked public repository describes the mcpvenom harness, 45 declarative attack scenarios and frozen result artifacts.
  • Claimed — In a controlled matrix of 12 MCP frameworks, 18 models and 45 scenarios (9,720 cells), run in July 2026, the authors report 2,113 vulnerable cells (22.9%); within the vulnerable cells they classify 12.1% as actual secret exfiltration. These are paper-reported benchmark outcomes, not observed deployment rates.
  • Claimed — The study's threat model assumes an attacker controls a malicious MCP server that is already registered with the agent. The authors report substantial variation by model and say framework-level differences are partly explained by incidental executor or tool-name behavior rather than deliberate security hardening.
  • Not established — The paper does not establish field prevalence, performance against current model versions, protection against integrity or availability harms, multi-turn attack behavior, or generalization across the roughly 50 MCP frameworks the authors estimate exist. No independent reproduction was conducted in this review.
  • Demonstrated — The linked mcpvenom repository README states that its Distribution License, Version 1.0, restricts use to authorized security testing, defensive validation and academic research, and does not permit redistribution or modification. This records the repository statement; the full license text was not independently reviewed here.

Strongest baseline

The study compares multiple framework-model combinations under a shared scenario matrix; it does not provide a matched measure of real deployment prevalence or compare the incidence of attacks in production.

Limitations

  • The rates are reported by the paper authors and were not independently reproduced in this review.
  • The attacker must control a malicious MCP server already registered with the target agent; the study does not measure how often such registration occurs in practice.
  • The matrix covered 12 of the authors' estimated roughly 50 frameworks and 45 scenarios across 23 of 25 taxonomy classes.
  • The experiment was single-turn and focused on confidentiality/exfiltration; integrity and availability harms were not measured.
  • Models were run in July 2026; eight model identifiers were not version-pinned, limiting exact temporal reproducibility.
  • The canary setup used synthetic secrets and controlled infrastructure, not real user credentials or production deployments.
  • The linked repository README describes its Distribution License, Version 1.0, as limiting use to authorized security testing, defensive validation and academic research and prohibiting redistribution and modification; the full license file and frozen artifacts were not accessible in this review.

What we still don't know

  • No independent team has yet been inspected reproducing the reported matrix or validating the full scoring and classification pipeline.
  • The study assumes a malicious server is already registered and does not measure real-world prevalence of that condition or generalization to deployment workflows.
  • The linked repository README and frozen-result description were inspected, but the harness code, raw artifacts and analysis scripts were not run or audited in this activation.

Why it matters

MCP tools can expose agents to instructions and responses supplied by external servers. This study reports that, in its controlled test setup, poisoning descriptions sometimes led agents to read or disclose planted secrets across several frameworks. The result motivates careful registration, permission and output controls, but the lab rates cannot be read as the frequency of incidents in deployed systems.
