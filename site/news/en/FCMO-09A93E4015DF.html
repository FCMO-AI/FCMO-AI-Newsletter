Cactus releases Needle 3, a laddered quantized model for offline tool use on small devices

Cactus Compute released Needle 3 as a 2-bit, laddered model for local tool calling, structured extraction and text embeddings on devices ranging from phones to microcontrollers. The public model family spans 29–121 million parameters and 2–20 layer subnetworks, with the company describing 9–29 MB quantized variants and 8–29 MB package/model configurations. Cactus reports speed and benchmark advantages on mobile tool calling and structured extraction, but these comparisons come from its own tests and mix a CQ2 mobile binary, f16 baselines under vLLM and a hosted DeepSeek API. Independent matched accuracy, power, latency and real-use measurements remain open.

Claim vs. evidence

  • DEMONSTRATED — Cactus Compute publicly released a Needle 3 package, source repository and model/runtime materials for local tool calling and structured extraction; PyPI dates cactus-needle 3.0.0 to 2026-09-17.
  • CLAIMED — Cactus describes Needle 3 as a 29–121M-parameter laddered model with deployable 2–20-layer subnetworks, CQ2 quantization and 9–29 MB model variants; its page also reports Raspberry Pi 5 speed ranges.
  • CLAIMED — Cactus reports that Needle 3 beats models ten times its size on mobile tool calls and matches models two to three times its size on extraction across vendor-selected evaluation suites. The comparison does not use a uniform hardware, precision or hosted-versus-local regime.

Strongest baseline

For base-model evaluation, the vendor compares against larger models on Mobile Actions (961 rows), DroidCall (200 rows), BFCL v4 (3,641 rows), DSTC8 extraction (1,813 turns) and SNIPS extraction (700 rows per setting). This is not a fully matched hardware/precision regime: Needle uses its shipped CQ2 binary, comparison baselines use f16 under vLLM, and DeepSeek V4 Flash is called through a cloud API.

The caveat that matters

  • All Needle 3 benchmark and speed figures inspected here are reported by Cactus Compute; no independent reproduction or matched test was performed.
  • The tool-calling and extraction suites are narrow. Performance does not establish general reasoning, reliable autonomous action or broad assistant capability.
  • The comparisons mix a 2-bit CQ2 Needle binary, f16 baselines under vLLM and a hosted DeepSeek V4 Flash API, so size/accuracy claims do not isolate parameter count or hardware efficiency.
  • Fine-tuning gains are vendor-reported using proprietary data and small downstream test sets; no independent held-out or cross-product evaluation was inspected.
  • Power draw, thermal behavior, sustained throughput, peak memory on named low-end devices and end-to-end application failure rates remain unmeasured independently.
  • Cactus states that the 360B-token structured training set is proprietary; data composition and training ablations are not available for review.

What remains unknown

  • The public comparison is vendor-run and uses mixed precision and serving regimes; independent matched accuracy and latency are unknown.
  • No independent power, thermal, memory or sustained-throughput measurements on the intended phone, wearable, robot or microcontroller deployment classes were checked.
  • The provenance and domain coverage of Cactus’s proprietary structured training set are not public in the release materials reviewed.

FCMO Lens

A small, deployable model that returns schema-constrained actions could move some tool use from cloud calls onto devices with tight memory or intermittent connectivity. If the reported size and task performance hold on target hardware, this changes the local inference design space; current evidence establishes a released implementation and vendor-run results, not independent device utility or broad capability.
