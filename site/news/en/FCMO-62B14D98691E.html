Unit 42 reports prompt-injection credential exposure in a tested AWS AgentCore Harness setup

On September 18, 2026, Palo Alto Networks Unit 42 published a technical report describing a controlled SupportCo simulation using AWS AgentCore Harness. Unit 42 reports that an indirect prompt injection could steer the default shell tool in its tested setup to expose an operator service credential that AgentCore Identity had resolved for a downstream MCP service; the researchers say they replayed that credential against their simulated service. AWS documentation confirms that shell and file_operations are available unless restricted with allowedTools, which scopes tool selection at InvokeHarness, and documents per-session microVM isolation and customer responsibility for input validation. Unit 42 says AWS closed its May disclosure as informative on June 10 under shared responsibility, citing customer-side controls. That disposition is not independently confirmed here. No independent reproduction, customer incident or prevalence estimate was inspected; the public account supports a bounded source-reported test, not a general AWS vulnerability or population-risk claim.

What actually changed

On September 18, 2026, Palo Alto Networks Unit 42 published a technical report describing a controlled SupportCo simulation using AWS AgentCore Harness. Unit 42 reports that an indirect prompt injection could steer the default shell tool in its tested setup to expose an operator service credential that AgentCore Identity had resolved for a downstream MCP service; the researchers say they replayed that credential against their simulated service. AWS documentation confirms that shell and file_operations are available unless restricted with allowedTools, which scopes tool selection at InvokeHarness, and documents per-session microVM isolation and customer responsibility for input validation. Unit 42 says AWS closed its May disclosure as informative on June 10 under shared responsibility, citing customer-side controls. That disposition is not independently confirmed here. No independent reproduction, customer incident or prevalence estimate was inspected; the public account supports a bounded source-reported test, not a general AWS vulnerability or population-risk claim.

Claim vs. evidence

  • CLAIMED — Unit 42 reports that, in its controlled SupportCo simulation, indirect prompt injection could steer the AgentCore Harness shell to expose an operator service credential resolved for a downstream MCP integration, which the researchers then replayed against their simulated service. This is one source-reported configuration, not evidence of a customer incident or widespread exposure.
  • DEMONSTRATED — AWS documentation states that shell and file_operations are available in every session unless restricted with allowedTools, and that allowedTools scopes model tool selection at InvokeHarness. The documentation also describes per-session microVM isolation and customer responsibility for input validation and prompt-injection prevention.
  • CLAIMED — Unit 42 says AWS closed its June 10 disclosure as informative under the shared responsibility model, citing allowedTools scoping and egress filtering as customer-side controls; no direct AWS case response or public AWS statement was inspected.

Strongest baseline

AWS documentation states that shell and file_operations are available in each session unless restricted, and that allowedTools controls model tool selection at InvokeHarness. It describes sessions as isolated microVMs and assigns customers responsibility for input validation and prompt-injection prevention. This is the documented configuration baseline, not an evaluation of the reported attack path.

The caveat that matters

  • The development records a bounded Unit 42 source-reported simulation, not an independently reproduced vulnerability or an AWS-confirmed security status.
  • No actual customer exposure, prevalence or exploit activity was demonstrated in the inspected material.
  • The source author sells security products and related services; its impact and mitigation framing warrants independent scrutiny.

What remains unknown

  • No independent test has reproduced Unit 42’s credential exposure in the reported configuration.
  • The June 10 AWS closure as informative is reported by Unit 42; no direct AWS response, advisory or versioned status change was inspected.
  • The report does not establish how many deployments use the relevant configuration or whether customers were exposed.

FCMO Lens

If the report is reproducible under the documented configuration, it shows that credential-vault encryption at rest and in transit does not by itself bound what a default shell tool can access after a credential is resolved for a downstream call. Managed-agent security reviews should distinguish caller permission to invoke a harness from the authority and in-process access granted to tools inside that harness. The report is one vendor’s controlled demonstration, with no independent reproduction or evidence of customer exposure.
