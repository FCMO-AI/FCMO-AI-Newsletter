A code-generation study reports that structural compliance can conceal incorrect answers

Adikari and Herath evaluated three cost-efficient models across eight combinations of model, coding-agent tool and prompt format on 992 Project Euler problems converted to Java Spring Boot methods. They report near-ceiling compliance with required method signatures and 7,936 executed requests, but only 12.9% of returned answers were correct; 38.4% of generated methods did not compute the value they returned. This is a single-generation, author-reported evaluation on a narrow algorithmic corpus, not a measured rate for enterprise code or deployed assistants.

What actually changed

Adikari and Herath evaluated three cost-efficient models across eight combinations of model, coding-agent tool and prompt format on 992 Project Euler problems converted to Java Spring Boot methods. They report near-ceiling compliance with required method signatures and 7,936 executed requests, but only 12.9% of returned answers were correct; 38.4% of generated methods did not compute the value they returned. This is a single-generation, author-reported evaluation on a narrow algorithmic corpus, not a measured rate for enterprise code or deployed assistants.

Claim vs. evidence

  • CLAIMED — The authors report that generated Java methods met the mandated signature while 38.4% of methods did not compute the value they returned, and only 12.9% of returned answers were correct in this evaluation.
  • CLAIMED — The reported results come from three cost-efficient models, four model/coding-tool pairings and two prompt layouts on 992 Project Euler problems in a one-shot Java Spring Boot generation regime.
  • CLAIMED — The authors report an inverse association between their semantic-compliance and correctness measures, but explicitly caution that denominators differ and that the correlation does not establish that attempting more causes lower accuracy.

Strongest baseline

The paper crosses Gemini Flash 3 with Cursor, GPT-5.4 mini with Cursor, and Claude Haiku 4.5 with both Cursor and Claude Code; each of these four model/tool pairings is evaluated under two prompt layouts. It compares structure/strategy classification with execution correctness on the same methods; there is no separate human-code or frontier-model control in the inspected study.

The caveat that matters

  • The experiment uses Project Euler numeric problems represented as Java Spring Boot methods; it does not measure enterprise application development, repository-level tasks or deployed coding-assistant failure rates.
  • Each task/configuration received one generation, so the reported proportions do not estimate variability across sampling runs or establish a stable model failure probability.
  • The corpus likely has contamination exposure: the authors note early Project Euler problems are widely discussed online and report that many literal matches cluster in the early range.
  • The paper reports partial generated-code coverage across configurations, varying from 80.1% to 100.0% in Table II; missing methods and runtime errors affect denominators.
  • The reported negative correlations do not establish that better semantic compliance causes lower accuracy. The paper explains that denominators and task difficulty differ; GPT-5.4 mini's strongest conditional correctness point is concentrated among easier early problem identifiers.
  • The paper's classification is syntactic/static and its harness only covers specified output patterns; complex semantics, human review, iterative repair, repository context and adversarially stronger test suites are not evaluated.
  • All results are author-reported; the research desk did not inspect raw generated artifacts, run the public/author code or independently reproduce the evaluation.

What remains unknown

  • The study's method classification, generated code counts and correctness results have not been independently reproduced; no author code artifact was located in this review.
  • Whether the measured structure/function gap occurs in repository-level, enterprise or iterative code-generation tasks is unknown; the current evaluation uses one-shot Project Euler-to-Spring methods.

FCMO Lens

The study evaluates structure and executed function on the same generated code, and reports that a valid signature can coexist with fabricated or incorrect output. If the narrow result generalizes, source-shape checks and answer-rate measures alone can miss severe failure modes in code-generation evaluations. The paper does not establish prevalence outside its specific tasks, models and one-shot setup.
