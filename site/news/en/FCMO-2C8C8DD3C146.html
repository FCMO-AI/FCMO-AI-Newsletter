onPanda reports faster alignment-data annotation through token-level correction

The paper presents onPanda, an interactive annotation workflow that corrects the first inappropriate token and continues generation from the revised prefix, preserving model-generated context and token-level correction traces. In a study of 21 image-description prompts with three annotators and Qwen3.5-35B-A3B rollouts, authors report median annotation time of 330 seconds per prompt versus 681 seconds for POTATO post-editing, with similar time to Argilla ranking and higher reported pairwise preference. The comparison tests whole workflows, so interface and annotation paradigm effects are confounded; its small single-task sample limits transfer. Authors also report large production-session and correction totals, which were not independently audited. A linked public Python repository contains data-conversion, supervision and benchmark code; no code execution or independent reproduction is reported here.

Evidence

  • Claimed — onPanda uses a locate-correct-continue loop that truncates a model response after the first corrected token, continues generation, and retains intermediate outputs for positive/negative supervision.
  • Claimed — In a controlled comparison on 21 image-description prompts, three annotators using Qwen3.5-35B-A3B rollouts recorded median time of 330 seconds per prompt with onPanda versus 681 seconds with POTATO post-editing; the authors report 66.7% pairwise win rate and 100% qualified-response coverage by design.
  • Claimed — The authors report 97.0% of tokens in qualified production responses were model-generated, across 131,996 annotation sessions, with about 388,000 token-level corrections; these deployment totals are not independently audited.
  • Not established — The study does not establish that the reported time or quality differences transfer to other task types, annotator populations, baselines or deployment settings, or that onPanda improves downstream model capability.

Strongest baseline

POTATO post-editing on the same 21 prompts: median 681 seconds versus onPanda 330 seconds; Argilla's four-candidate ranking median was 336 seconds. These are complete-workflow comparisons rather than an isolated test of token-level correction.

Limitations

  • The primary controlled comparison includes only 21 image-description prompts and three annotators.
  • Each annotation platform differs in both interface and paradigm, so the comparison cannot isolate which design feature causes the time difference.
  • The main pairwise win rate uses an LLM judge; the separate human preference result is based on the same small study.
  • Reported production session counts and correction totals are author-reported and were not independently audited.
  • No downstream model training result establishes that these annotations improve model capability or generalization.
  • The public repository was inspected but not executed; no independent reproduction was located.

What we still don't know

  • The 21-prompt annotation-time and quality comparison has not been independently reproduced; interface and paradigm are confounded.
  • The paper's production session totals and correction statistics have no independent audit in the inspected evidence.
  • It remains unknown whether token-level correction data improves downstream model behavior relative to matched alternatives.

Why it matters

Human annotation is a costly part of alignment-data production. Correcting a model response in place and retaining each correction may reduce annotation effort while yielding finer supervision than final-answer edits or response-level preferences. If the small workflow comparison generalizes, it could influence data-pipeline design, but it does not demonstrate improved model performance or general productivity gains.
