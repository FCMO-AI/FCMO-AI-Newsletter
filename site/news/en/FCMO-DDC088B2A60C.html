In brief · Agents and memory

GEPA-Curator reports better agent prompt optimization by filtering noisy feedback and retrieving past successes

A preprint introduces GEPA-Curator, which curates task rollouts before reflective prompt updates and retrieves prior successful trajectories as reference context. The authors report better held-out results than GEPA/ACE across WebArena, ALFWorld, AppWorld and τ-bench, using Gemini 3.1 Pro Preview or Claude Opus 5 as optimizer models and gpt-oss-120B as actor. Across four WebArena domains, the reported aggregate is 82.1% vs 78.7% for GEPA with Gemini and 84.5% vs 79.5% with Opus. On four additional test sets, reported average gains over GEPA/ACE range from 5.0 to 14.3 percentage points with Gemini and 8.1 to 12.6 points with Opus. These are author-reported benchmark results from manually seeded prompt optimization; they do not establish open-ended goal discovery, persistent weight improvement or general autonomous self-improvement.

Evidence

  • Demonstrated — GEPA-Curator selects task experiences and retrieves prior successful trajectories to provide cleaner context to a reflective prompt optimizer.
  • Claimed — The authors report higher held-out WebArena aggregate success for GEPA-Curator than GEPA with both Gemini 3.1 Pro Preview and Claude Opus 5 optimizer models.
  • Claimed — The authors report mean held-out gains over GEPA and ACE on ALFWorld, AppWorld and tau-bench in their tested configurations.
  • Inferred — The results establish general autonomous self-improvement or persistent model-weight improvement.

Strongest baseline

The paper compares against GEPA and ACE using the same seed prompt, evaluator, action limits and environment configuration for the main WebArena setup; it also reports benchmark-specific split and rollout budgets.

Limitations

  • One author-reported preprint with no independent reproduction located.
  • Main experiments optimize manually written seed prompts on benchmark task sets; they do not test open-ended goal or target selection, model-weight updates or broad transfer outside the evaluated tasks.
  • Held-out sets are part of benchmark-specific optimization and final model selection uses validation scores; no independent confirmation distribution beyond those benchmark test splits is reported.
  • The Meta-Harness extension uses one optimization run per method and setting, so run-to-run variance is unknown there.
  • Evaluator, environment and task-diagnosis errors remain possible; the paper itself reports some task diagnoses later reversed.

What we still don't know

  • No independent reproduction has verified the reported held-out gains, task curation decisions or cost accounting.
  • The results do not establish transfer to unseen task families or quantify persistent prompt-regression risk after mutations.
  • Meta-Harness-Curator results use one optimization run per setting.

Why it matters

The paper isolates a concrete failure mode in experience-driven agent improvement: execution failures may come from the prompt, harness, environment or evaluator, so treating every failure as useful learning signal can damage later behavior. In the tested benchmark regime, selecting cleaner task histories and supplying past successes improved reported held-out prompt performance. This is useful evidence for designing self-improvement loops, while leaving independent reproduction and broad transfer unresolved.
