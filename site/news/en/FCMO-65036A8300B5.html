OpenAI reports large gains on coding evaluations for low-resource programming languages

In an Oct 19 post, OpenAI reports improved results for GPT-6 models on two coding evaluations involving lower-resource languages. On MultiLangBench, which asks models to build a SQLite-compatible database engine across 20 languages, OpenAI reports an average test pass rate of 87.4% for GPT-6 Astra versus 26.8% for GPT-5.6 Sol; GPT-6 Luna scores 40.3% at a stated approximately 78% lower estimated API cost. On a separate COBOL migration evaluation, OpenAI reports 86.6% accuracy for GPT-6.1 Sol at low reasoning effort versus 5.4% for GPT-5.6 Sol, and 97.9% at higher effort. OpenAI released the MultiLangBench setup and test suite. These are company-reported evaluation results, not independently reproduced or evidence of production migration safety.

Evidence

  • Claimed — OpenAI reports that GPT-6 Astra achieved an average 87.4% test pass rate on MultiLangBench across 20 languages versus 26.8% for GPT-5.6 Sol; GPT-6 Luna scored 40.3% at approximately 78% lower estimated API cost than GPT-5.6 Sol.
  • Claimed — OpenAI reports 86.6% accuracy for GPT-6.1 Sol at low reasoning effort on its COBOL migration evaluation versus 5.4% for GPT-5.6 Sol at the same setting, with GPT-6.1 Sol reaching 97.9% at higher effort.
  • Demonstrated — The public OpenAI MultiLangBench repository describes a SQLite 3.40.1 implementation task and test construction from SQLite TCL tests; it states 24,000 of 51,000 source tests were converted and recommends a 272-test subset for ordinary lower-cost comparisons.
  • Not established — The reported scores do not establish independently reproduced performance, behavior preservation in production systems, reduced expert-review burden, or realized economic savings.

Strongest baseline

OpenAI compares GPT-6 Astra and GPT-6 Luna with GPT-5.6 Sol on MultiLangBench, and GPT-6.1 Sol with GPT-5.6 Sol at the same low reasoning setting on COBOL migration. The inspected source does not establish cross-lab comparability or independent replication.

Limitations

  • The performance figures are OpenAI-reported; the research desk did not execute or reproduce either evaluation.
  • The public repository documents MultiLangBench, but the described SQLite task is not a direct measure of general software maintenance or full production migration.
  • The repository README says 24,000 of 51,000 SQLite TCL tests were converted and recommends a 272-test subset for routine lower-cost evaluations; representativeness of that subset remains to be assessed.
  • The inspected public repository does not document the separate COBOL migration evaluation's task corpus or hidden-test design.
  • The post itself says production migration requires expert review and testing against system business rules and dependencies; production safety and realized economic impact are not established.
  • The inspected GitHub repository root exposes the README, requirements, scripts and tests but no separate per-language result file; the OpenAI post says such results are released, and their artifact location was not identified in this pass.

What we still don't know

  • Neither evaluation's reported scores have been independently reproduced; repeated-run uncertainty and exact model prompts/settings were not inspected.
  • The repository README notes 24,000 convertible tests from 51,000 SQLite TCL tests and recommends a 272-test subset for ordinary comparisons; how the reported averages vary across sampled tests and language-specific coverage is not established here.
  • The COBOL migration evaluation details and a public runnable artifact were not located in the inspected post and linked repository.
  • No production migrations, behavior drift rates, expert-review costs, deployment outcomes or economic savings were measured in the inspected sources.
  • OpenAI says per-language results accompany the released evaluation, but the inspected repository root exposes no separate result table/file and the inspected README sections do not show per-language scores; the result artifact path remains unidentified.

Why it matters

COBOL, Fortran and other languages with smaller training and documentation corpora remain embedded in important software. Stronger coding and behavior-preserving migration could reduce a practical maintenance bottleneck if these results transfer to real repositories. The evidence currently measures controlled evaluation tasks, and expert review and system-specific testing remain necessary; neither production impact nor economic savings are established.
