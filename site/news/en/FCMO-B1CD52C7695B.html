SwarmEvolve reports faster program search with latent agent swarms

Jiang and Karniadakis introduce SwarmEvolve, which runs 10 swarms of 45 Qwen3 agents that reason for 40 steps in latent space, select diverse traces and pass their KV caches to a summarizer that proposes programs. On 21 evaluator-driven mathematics and scientific-computing tasks, the authors report the highest average score against OpenEvolve, ShinkaEvolve and CodeEvolve across Qwen3 8B, 14B and 32B-FP8, using three seeds and one GPU plus eight CPU cores per model setup. With Qwen3 8B they report improving three AlphaEvolve constructions. These are paper-reported results, not independently reproduced here. The experiments are limited to the selected tasks and compute regime; the linked GitHub repository is now accessible and contains benchmark tasks, evaluators, baselines and analysis, but its README says the core SwarmEvolve code is coming soon; the method still cannot be independently run from that repository.

Evidence

  • Demonstrated — The Nov 5, 2026 arXiv paper describes a program-search system with 10 swarms of 45 latent agents per round, 40 latent reasoning steps per agent, novelty filtering and KV-cache aggregation for a decoding summarizer.
  • Claimed — The authors report that SwarmEvolve has the highest mean score of the compared frameworks across 21 evaluator-driven tasks for each of Qwen3 8B, 14B and 32B-FP8; each result averages three seeds under one-GPU and eight-CPU-core settings.
  • Claimed — For Qwen3 8B, the authors report median times of 4–8 minutes for SwarmEvolve to reach the comparison frameworks’ 60-minute scores on the tested tasks, with some tasks not reaching the target within the 60-minute SwarmEvolve run.
  • Claimed — The authors report that SwarmEvolve with Qwen3 8B improves three constructions first reported by AlphaEvolve with frontier models; these are benchmark-specific program-search results, not proof of broad autonomous scientific discovery.
  • Not established — The inspected evidence does not independently reproduce the comparisons or establish transfer to open-ended scientific research, different evaluators, models, hardware or workloads.

Strongest baseline

Reported mean scores for Qwen3 8B: SwarmEvolve 0.804, OpenEvolve 0.693, ShinkaEvolve 0.642 and CodeEvolve 0.700; Qwen3 14B: 0.837, 0.771, 0.686 and 0.739; Qwen3 32B-FP8: 0.869, 0.774, 0.733 and 0.731. These are paper-reported cross-task means.

Limitations

  • All comparative results are reported by the paper authors and use three seeds.
  • The baselines retain their default configurations; identical time limits do not isolate every implementation or tuning difference.
  • Results are on 21 fixed evaluator-driven tasks, including 16 drawn from AlphaEvolve appendix tasks and five designed scientific-computing tasks; they do not establish open-ended scientific discovery.
  • The largest tested model uses a single H100 and the method requires standard-attention models; KV-cache memory grows with swarm and reasoning length.
  • The author-linked repository is accessible and includes benchmark tasks/evaluators, baseline copies/scripts and analyses, but its README says the core SwarmEvolve implementation is coming soon; no method implementation was independently run.

What we still don't know

  • The reported performance and efficiency results have not been independently reproduced. The linked repository now exposes benchmarks and baseline assets, but says the core SwarmEvolve code is coming soon.
  • The 21 tasks use explicit program evaluators; performance transfer to open-ended research tasks or externally authored problem suites is not established.

Why it matters

If independently reproduced, latent communication and large low-cost swarms could make evaluator-guided program search more capable per unit time on mathematical constructions and scientific-computing tasks. The paper reports measurable gains in this bounded setting, while leaving performance outside these fixed evaluators, broader scientific discovery and independent reproduction unresolved.
