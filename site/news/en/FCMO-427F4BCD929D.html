Flash-dLLM reports faster diffusion-model decoding with fused KV caching and self-verification

A September 2026 paper proposes Flash-Cache, which fuses KV-cache operations, and Flash-Verify, which lets a diffusion LLM draft and verify candidate tokens without an auxiliary model. On one NVIDIA A100 80GB running LLaDA-1.5, the authors report 5.1× speedup over Elastic-Cache on GSM8K at 512 tokens and 11.0× on HumanEval at 512 tokens. Across the paper’s 512-token settings, reported throughput reaches 210.6 tokens/s on GSM8K, 210.1 on MATH, 185.6 on HumanEval and 148.2 on MBPP; accuracy varies by task, and the fastest setting is not always the most accurate. The authors provide an Apache-2.0 repository with benchmark scripts, but no code was run; its README flags a possible difference between paper and adapter descriptions of the verification threshold. These remain author-reported results from one model and hardware setup.

Evidence

  • Demonstrated — The primary arXiv paper describes Flash-Cache and Flash-Verify for diffusion LLM inference.
  • Claimed — The authors report experiments on LLaDA-1.5 running on a single NVIDIA A100 80GB and speedups of 5.1× on GSM8K and 11.0× on HumanEval over their strongest prior baseline.
  • Claimed — The paper’s 512-token results report throughput of 210.6 tokens/s on GSM8K, 210.1 on MATH, 185.6 on HumanEval and 148.2 on MBPP for the combined method, with task-dependent accuracy trade-offs.
  • Demonstrated — The authors provide a public Apache-2.0 repository with benchmark scripts and setup guidance; this review inspected the README but did not execute the code or verify a reproduction.

Strongest baseline

The paper and authors’ README identify Elastic-Cache as the strongest prior baseline for the headline 5.1× GSM8K-512 and 11.0× HumanEval-512 ratios. Separate table ratios compare against greedy no-cache decoding. Baseline, quality and throughput depend on task and configuration.

Limitations

  • All reported measurements are author-reported; no independent reproduction was performed.
  • Experiments use one A100 80GB and one model, LLaDA-1.5; performance on other diffusion-model families and hardware is unknown.
  • The fastest configuration is not consistently the most accurate; reported accuracy trade-offs vary by benchmark and generation length.
  • Throughput speedups depend on the baseline and setup; the headline gains do not establish comparable gains against all autoregressive models or in production serving.
  • The author README notes a potential difference between the paper formulation and the adapter documentation for the verification threshold; exact benchmark reproduction should reconcile this before interpreting threshold sweeps.

What we still don't know

  • No independent reproduction or cross-model validation of the reported throughput, accuracy or memory results was performed. The current public repository is not pinned to a commit, and its README flags possible paper/adapter differences in verification-threshold semantics.
  • Generalization to other GPU generations, longer/open-ended workloads and production batch distributions is not established.

Why it matters

If the reported gains hold on other diffusion language models and serving systems, fused cache handling plus same-model verification could change inference-engine design and narrow the efficiency gap for diffusion LLMs. The paper’s single-model, single-GPU regime and task-dependent accuracy trade-offs sharply bound that implication.
