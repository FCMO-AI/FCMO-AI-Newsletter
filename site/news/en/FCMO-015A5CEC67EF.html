What changed

A NeurIPS 2026 TTCL Workshop paper introduces JAZ, whose invoke primitive lets a model generate executable code with recursive model calls while exposing prompt inputs and execution history as variables. In the authors’ three-run StuLife evaluation using GPT-5.4 nano, JAZ reports 69.9% pass rate on 207 far-recall tasks versus 61.8% for Letta (MemGPT), at a reported average cost of $18.30 versus $42.10. On AppWorld self-improvement, it reports 74.2% task-goal completion versus 69.9% for ACE. These are paper-reported benchmark results, not independent replications; the paper documents its protocols and notes baseline implementation differences. The authors’ reproduction repository adds a material version caveat: the published runs used mostly dirty development checkouts, two run commits are no longer available, and the closest installable release is not the literal run version. Its StuLife fork also changed the tool surface and task data for 132 of 1,284 tasks, applying those changes across all five arms.

Evidence

  • Claimed — The authors define JAZ’s invoke primitive as an LLM-generated code function that can recursively call the model and access both its inputs and REPL history as variables.
  • Claimed — In three reported runs with GPT-5.4 nano on StuLife, the paper reports a 69.9% pass rate on 207 far-recall tasks for JAZ invoke versus 61.8% for Letta v0.16.8 (MemGPT), with mean costs of $18.30 and $42.10 respectively.
  • Claimed — On the AppWorld test-challenge split, the paper reports 74.2% task-goal completion for JAZ invoke versus 69.9% for ACE; reported total costs are $20.90 and $30.60, respectively.
  • Claimed — The authors’ reproduction repository says the published runs used development checkouts, mostly with uncommitted changes; two run commits are no longer available, and the closest installable release is not the literal version used. It also documents StuLife tool and task-data changes affecting 132 of 1,284 tasks, applied uniformly across five arms.

Strongest baseline

Letta v0.16.8 (MemGPT) for StuLife far recall; ACE for AppWorld continual self-improvement.

Limitations

  • The reported gains are benchmark-specific and do not establish general long-horizon memory or self-improvement capability.
  • The StuLife table reports three independent runs; AppWorld self-improving methods use six runs, and the paper reports standard errors.
  • Baseline implementations are not identical to every official external implementation; the paper describes its ablations and prompt setup.
  • No independent replication, deployed-system result or production reliability measure was inspected.
  • The authors’ reproduction repository says two commits used by published runs are no longer available and most runs used dirty development checkouts; the closest installable JAZ version is not the literal run version. Exact-run code reproduction is therefore limited.
  • The reproduction repository’s StuLife fork changes the agent-facing tools and repairs task data for 132 of 1,284 tasks; changes are applied to all five reported arms, so within-fork comparisons remain possible but are not direct comparisons on unmodified upstream StuLife.

What we still don't know

  • No independent reproduction of the JAZ results or matched-cost analysis was inspected; reported task scores and costs come from the authors’ benchmark implementations.
  • The paper identifies implementation and prompt differences among baseline systems, including an out-of-box AppWorld CodeAct prompt with benchmark-specific workflow guidance; generality beyond these setups is unknown.
  • The authors’ reproduction package says most published runs came from dirty development checkouts, two commits no longer exist, and the closest installable release is not the exact run version; exact-run reproduction is therefore not currently possible from the published release alone.

Why it matters

If independently reproduced, the results would suggest that some long-horizon recall and cross-task self-improvement functions can emerge from a recursive code-oriented agent loop, potentially reducing the need for specialized harness components in these settings. The evidence remains bounded to two benchmark suites and author-run comparisons.
