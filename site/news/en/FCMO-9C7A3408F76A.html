A Sep 17, 2026 arXiv preprint introduces SIFT, which uses pairwise LLM judgments and a regularized Bradley–Terry ranking signal to steer a disaggregated search over coding-agent modifications, reserving more expensive task evaluations for selected candidates. Evidence

  • Claimed — SIFT uses pairwise LLM judgments of candidate code patches, aggregates wins and losses with a regularized Bradley–Terry model, and uses those scores for rank-based parent sampling in a disaggregated search pipeline; expensive task evaluations are reserved for selected nodes.
  • Claimed — On the authors' Polyglot-225 experiments, SIFT with Qwen3-Coder-30B and a Qwen3-Coder-480B judge reaches 31.1%, compared with 30.5% for HGM in the reported comparison. With o3-mini and a GPT-5.4 judge, SIFT reaches 35.1%, compared with 30.7% for DGM, which the paper says used 80 search nodes while the SIFT run used 30 expansion steps.
  • Claimed — On TerminalBench 2.1, the authors report three repeated full evaluations averaging 36.7% for the agent selected by judge rank and 28.1% for the agent selected by search-score rank, after search used a sampled 50-task subset.
  • Demonstrated — The v1 paper's resource accounting is internally inconsistent for the o3-mini/GPT-5.4 SIFT result: Table 3 lists 20 expansion steps, $86.8 API cost, 59 CPU hours and 2.1 hours wall time, while adjacent prose describes 30 steps, $150 in credits, 42 CPU hours and under five hours. This review does not reconcile the figures.

Strongest baseline

For Qwen3-Coder-30B, the paper reports 31.1% for SIFT versus 30.5% for HGM. For o3-mini with GPT-5.4 judge it reports 35.1% versus 30.7% for DGM, but the paper compares 30 SIFT expansion steps with 80 DGM search nodes. On TerminalBench the judge-ranked candidate's repeated evaluation mean exceeds the candidate chosen by search-subset accuracy; this is a selector comparison, not a matched generalization claim.

Limitations

  • All performance results are author-reported in a single arXiv preprint; no independent reproduction was performed.
  • The o3-mini/GPT-5.4 resource totals and expansion-step count conflict between Table 3 and adjacent prose; resource efficiency cannot be inferred from that row without clarification.
  • The reported comparisons use specific coding, expansion and judge models; transfer to other models, patch distributions and agent harnesses is not established generally.
  • TerminalBench search uses a 50-task subset before repeated full evaluations; selected-agent outcomes do not establish that judge ranking is reliable across task distributions.
  • No public source-code link was listed on the arXiv record during this review, and no execution was attempted.

What we still don't know

  • The paper's Table 3 and adjacent prose disagree on steps, API credits and CPU hours for the o3-mini/GPT-5.4 SIFT run.
  • No independent reproduction of the Polyglot or TerminalBench results was located or performed.
  • No implementation repository link appears in the arXiv record inspected for v1.

Why it matters

If independently reproduced with reconciled accounting, cheap pairwise judging could help recursive coding-agent research spend fewer benchmark runs on weak candidate modifications. The current evidence is one author-run preprint; it does not establish a general compute advantage, and its reported resource figures conflict for a key run.
