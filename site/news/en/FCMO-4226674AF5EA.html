A preprint reports that live tool-progress signals improved post-tool latency in one serving-engine experiment

Liu et al. propose exposing execution progress from running agent tools to the serving system for KV-cache decisions. Their preprint reports a harness reading progress from tool output and environment state without changing the agent-visible result path, and an end-to-end experiment in a production engine. The authors report 20.7% lower p90 time to first token after tool calls with HBM only and 20.8% with HBM plus DRAM compared with LRU. These are paper-reported results, not an independent reproduction or evidence of general serving-system gains.

Their preprint reports a harness reading progress from tool output and environment state without changing the agent-visible result path, and an end-to-end experiment in a production engine. Claim vs. evidence

  • DEMONSTRATED — Liu, Zhang, Li and Zhang posted arXiv:2609.18849v1 on 2026-09-16, proposing that agent tools expose live progress to guide serving-side KV-cache decisions.
  • CLAIMED — The authors report that their harness recovered progress signals from four public agent corpora and that the signals improved prediction accuracy at tested KV-cache decision points.
  • CLAIMED — In the authors’ end-to-end production-engine experiment, live progress-based scheduling reduced p90 time to first token after a tool call by 20.7% in an HBM-only configuration and 20.8% with HBM plus DRAM versus LRU.

Strongest baseline

LRU for end-to-end p90 post-tool TTFT; four published predictors for prediction accuracy.

The caveat that matters

  • Results are from one author-reported preprint evaluation; no independent replication or peer review was established in this check.
  • A bounded search did not locate an inspectable author implementation or independent rerun; this is not proof none exists.
  • The 20.7% and 20.8% figures are p90 time-to-first-token after tool calls in two reported memory configurations; they are not general end-to-end agent latency or throughput gains.
  • Some tool calls expose no parseable progress, and the method depends on signals available from the tool or harness.

What remains unknown

  • The p90 post-tool TTFT improvements are author-reported; the research desk did not run the experiment or audit full workload/hardware details.

FCMO Lens

Tool execution can leave an agent request’s KV cache occupying scarce GPU memory while the agent waits. If the reported gains transfer, live tool progress could improve post-tool responsiveness and cache scheduling. Current evidence supports a specific paper-reported result, not a general performance guarantee.
