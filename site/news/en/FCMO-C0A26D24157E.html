EvoHarnessBench reports competence losses as agent tool, skill and specialist pools expand

The v3 preprint introduces EvoHarnessBench, which tests how agent performance changes as the externally supplied pool of tools, reusable skills or specialist agents expands. Its 17 constructed streams contain 802 unique tasks derived from two verifier-based agent benchmarks. Evidence

  • Claimed — The v3 preprint describes EvoHarnessBench, a controlled benchmark of externally expanding tool, skill, and specialist-agent harnesses, built from 17 multi-stage streams and 802 unique tasks drawn from verifier-based benchmarks.
  • Claimed — The authors report that exposing agents to cumulative expanding harnesses can lower performance on previously solved tasks even when the model and prompt stay fixed; the reported drops differ by tools, skills and specialist agents (12.1%, 13.8% and 46.4%, respectively).
  • Claimed — Across the paper's tested self-evolving methods and benchmark settings, gains are inconsistent, and retaining earlier competence can conflict with adapting to newly introduced capabilities.

Strongest baseline

The task-specific harness reference exposes only capabilities annotated as required for each task, compared with the full cumulative harness in deployment evaluation. This is a controlled benchmark reference, not a production baseline.

Limitations

  • All performance figures are author-reported; no independent reproduction was performed in this activation.
  • The deployment evaluation holds model and prompt fixed while expanding the exposed harness; it does not establish that every real system will regress as tools or agents are added.
  • The 17 streams and 802 unique tasks are constructed from EnterpriseOps-Gym and Agents' Last Exam; they are not a representative sample of production workloads.
  • Skill-to-task association uses heuristic matching between skill content and verifier-checked outcomes, which the authors state may not identify necessary or sufficient skills.
  • Some tables compare system configurations with distinct underlying harnesses; the authors omit Claude Code from the main controlled comparison and report it separately.

What we still don't know

  • The paper links benchmark materials, but the benchmark repository, task data, harness implementations and run configuration were not inspected in this review.
  • The reported harness-expansion effects and adaptation comparisons have not been independently reproduced.
  • The paper evaluates constructed streams from two verifier-based benchmark sources; real production harness growth and broader task distributions are not measured.

Why it matters

Agent systems increasingly gain tools, reusable procedures and specialist agents over time. This paper tests that growth as an evaluation variable and reports that broader harnesses can impair performance on earlier tasks, even when the underlying model and prompt remain fixed. The result motivates tracking retention separately from adaptation, while remaining limited to author-run benchmark streams rather than measured production systems.
