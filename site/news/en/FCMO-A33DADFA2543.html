OpenAI makes the Decisions API generally available for bounded classification, routing and scoring

OpenAI made the Decisions API generally available on Oct 22, 2026. The dedicated endpoint turns text, image and JSON inputs into bounded probabilities, choices or scores, currently using GPT-6 Luna; the API guide allows up to 400 questions per request and documents prompt caching and native GPT-Live integration. OpenAI lists $0.10 per million uncached input tokens and no output-token charge, subject to caching, regional and long-context terms. The company claims up to 10× lower latency than GPT-6 Luna through the Responses API, but publishes no benchmark protocol in the reviewed launch materials. Independent performance, adoption and realized economic effects remain unestablished.

Evidence

  • Demonstrated — OpenAI announced general availability of the Decisions API on 2026-10-22. Its documentation describes POST /v1/decisions, currently supports gpt-6-luna, and returns a probability, a choice among supplied values, or a rubric-based score from text, images and JSON input.
  • Demonstrated — The published API guide allows up to 400 questions in one request and documents prompt caching and native GPT-Live integration. OpenAI lists uncached input at $0.10 per million tokens, cached input at a discounted rate, and no output-token charge for this endpoint; regional-processing premiums and long-context multipliers can apply.
  • Claimed — OpenAI says Decisions returns bounded answers up to 10 times faster than GPT-6 Luna through the Responses API. The source does not give a workload, concurrency level, geographic condition, latency statistic or independent benchmark for this comparison.
  • Not established — No independent latency/accuracy comparison, broad customer adoption, realized cost reduction, or effect on end-to-end workflow outcomes was established in the reviewed sources.

Strongest baseline

OpenAI identifies GPT-6 Luna through the Responses API as the latency comparison. No matched benchmark protocol, accuracy comparison, concurrency, input distribution or uncertainty interval is published in the reviewed sources.

Limitations

  • All launch and API details are first-party OpenAI statements. Published documentation establishes the offered interface and listed prices, not independent runtime behavior, invoice outcomes or customer performance.
  • The claimed up-to-10× speed comparison has no disclosed workload or latency statistic in the reviewed sources; it should not be generalized to arbitrary prompts or applications.
  • Only GPT-6 Luna is documented as supported at launch. Whether typed outputs preserve accuracy for a given application must be evaluated on that task.
  • Regional-processing premiums, long-context multipliers and cache-write pricing can affect total cost. No workload-level cost calculation is reported here.
  • No independent adoption, productivity or end-to-end economic effect was found.

What we still don't know

  • The up-to-10× speed comparison lacks a public workload and measurement protocol in the reviewed materials, and no independent latency/accuracy comparison was located.
  • Published token rates do not establish realized customer cost or end-to-end productivity impact; billing terms and regional/long-context multipliers affect total cost.

Why it matters

Many agent and application workflows spend time and compute on repeated bounded decisions such as routing, classification and scoring. A specialized endpoint with a published input-only price and a vendor-reported speed advantage could change the cost and latency frontier for those workloads. Whether it improves end-to-end systems depends on task accuracy, concurrency, integration overhead and actual usage; those outcomes are not yet independently measured.
