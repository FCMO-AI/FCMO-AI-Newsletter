Evidence

  • Demonstrated — The preprint and author repository disclose a benchmark design built from real research artifacts: each task removes a paper contribution from its released code, gives the agent the repository and development feedback, and withholds the final evaluator and workloads. The pass criterion is to beat the human reference on every held-out workload and metric.
  • Claimed — The authors report 12 evaluated model-and-harness systems with one run per task over 48 public tasks spanning 13 computer-science domains. Claude Opus 5.5 in Claude Code passed 58% of its runs; no agent passed any of 16 tasks. These are single-run author-reported benchmark outcomes, not a repeatability estimate.
  • Demonstrated limitation — The paper pairs each model with one harness and settings, so the reported ranking does not isolate model weights from harness behavior. The author's repository lists 13 model entries across 48 tasks; it documents Kimi K2.7 as the zero point for the capability-index fit, reconciling that count with the 12 agents evaluated for pass outcomes.

Strongest baseline

The original published implementation retained as the human reference for each task, evaluated on the paper's workloads and held-out workloads.

Limitations

  • The paper reports one run per task for each evaluated model-and-harness system; repeated-run reliability is unknown.
  • Each model is paired with a different harness and settings, so the leaderboard is not a model-only comparison.
  • The 58% result is from Claude Opus 5.5 in Claude Code on this benchmark and does not establish general autonomous research capability or superiority across other tasks.
  • The public benchmark contains 48 of 150 planned tasks; unseen-task and selection effects remain open.
  • No independent reproduction or validation of the authors' full task and judge pipeline was performed in this review.

What we still don't know

  • No independent task replay, reference-parity check or audit of the full benchmark selection and scoring pipeline was performed in this review.
  • One run per task does not estimate run-to-run variance, and model identity is confounded with harness, reasoning settings and token limits.
  • The author repository says 48 of 150 planned tasks are public; performance on the remaining tasks and later releases is not established.

Why it matters

If its tasks and hidden evaluation behave as described, this benchmark measures whether agents can improve published systems under realistic repository, workload and cost constraints across a broad set of computer-science domains. It also makes a useful distinction between partial score gains and fully passing every held-out metric. The reported leaderboard remains a single run per task and pairs each model with one harness, so it does not isolate model-only capability or run-to-run reliability.
