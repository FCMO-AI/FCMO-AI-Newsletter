SpecGuard uses Lean certificates to detect task–test conflicts before coding agents run

Biyani and Dvijotham introduce SpecGuard, a pre-execution verifier for coding tasks whose natural-language intent may conflict with their tests. Separate agents formalize the task description/codebase and the test requirements, and a Lean kernel checks whether the generated representations can both be satisfied; the result may be conflict, no-conflict or inconclusive. In the authors’ mutated SWE-bench evaluation, GPT-5.6 Sol formally certified 51.1% of conflicts, while its conflict-miss rate was 8.1% versus 39.8% for an LLM-judge baseline. On 22 selected naturally occurring GitHub conflicts, the CLI returned nine conflict verdicts, eight with Lean certificates. These are author-reported preprint results. The kernel proves inconsistency between generated formal representations; semantic fidelity to the original task remains a separate and material limitation.

Claim vs. evidence

  • DEMONSTRATED — Biyani and Dvijotham published the SpecGuard preprint, arXiv:2610.09159v1, on 2026-10-06.
  • CLAIMED — On mutated SWE-bench tasks, the authors report that GPT-5.6 Sol produced Lean conflict certificates for 51.1% of conflicts; its conflict-miss rate was 8.1%, compared with 39.8% for an LLM-judge baseline. The authors report a 6.0% false-positive rate for SpecGuard and 2.3% for the judge on corresponding unmutated tasks.
  • CLAIMED — On a selected set of 22 naturally occurring GitHub test conflicts, the authors report nine CLI conflict verdicts, eight with Lean certificates and one with execution-only evidence; the remaining outcomes were twelve inconclusive and one no-conflict.
  • CLAIMED — The authors state that a Lean certificate proves inconsistency between the generated task specification and formalized tests; it does not by itself establish that either formalization faithfully represents the original task.

Strongest baseline

An LLM-judge majority vote over five judgments, plus a Python reference-model baseline; the latter receives paired original and corrupted tests, unlike the main SpecGuard comparison.

The caveat that matters

  • A kernel-checked proof establishes inconsistency between generated representations, not that the specification or test transcription faithfully captures the source task.
  • The authors' manual audit found 52 of 60 reviewed formalizations faithful, six spurious and two weak; in an audit of incorrect verdicts, connector alignment was the most common failure source.
  • On corresponding unmutated tasks, SpecGuard's reported false-positive rate was 6.0%, higher than the LLM judge's 2.3%; treating inconclusive outcomes as blocked increases coverage but withholds some unmodified tasks.
  • The method targets behavior expressible as executable value semantics and assumes the task description is trusted; adversarial modification of the description is outside its threat model.
  • The 22 natural conflicts were selected from GitHub issues/PRs and are not a prevalence sample; nine received conflict verdicts and twelve were inconclusive.
  • The paper-linked GitHub repository returned 404 in this activation. Reported results have not been independently reproduced.

What remains unknown

  • The arXiv paper links a GitHub repository, but the URL returned 404 in this activation; code and pinned revisions could not be inspected.
  • No independent reproduction of the three-run GPT-5.6 Sol comparison, model-specific rates, cost or natural-conflict CLI evaluation was established.
  • A certificate proves a contradiction between generated formalizations, but semantic correspondence to the original task remains a separate assumption; six of 60 manually reviewed formalizations were spurious and two weak.
  • Evaluation is limited to coding tasks with value-semantics behavior and a trusted task description; coverage of side effects, concurrency, external dependencies and adversarial task descriptions is unknown.

FCMO Lens

If reproduced, a pre-execution check that surfaces impossible or adversarial task/test combinations with an independently checkable certificate could prevent some coding agents from being rewarded for test gaming before they act. The method explicitly separates a model's interpretation from the kernel's proof and allows inconclusive outcomes. Its usefulness depends on faithful translation of task intent and tests, and the current evaluation is limited to selected coding-task settings.
