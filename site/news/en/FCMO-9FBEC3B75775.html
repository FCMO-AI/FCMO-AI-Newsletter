What changed

Google’s public ARTEMIS repository provides natural-language Android automation through a reactive Flash profile and a slower plan-and-verify Pro profile, with CLI, Python SDK and MCP integrations for coding environments. The project describes accessibility-tree and OCR targeting with visual fallbacks, execution traces and history summaries. Its README claims 99%+ task completion on AndroidWorld’s 100+ multi-step tasks, but gives no model/version, per-task scores, trial counts or independent evaluation; this remains a first-party claim.

Evidence

  • Demonstrated — Google maintains a public Apache-2.0 repository with Android automation code, CLI, Python SDK and MCP integration; repository metadata reports creation on August 13, 2026.
  • Claimed — The project documents a Flash reactive profile typically taking 3–5 seconds per step and a Pro planning/verification profile typically taking 15–40 seconds per step, with different safety and reporting features.
  • Claimed — The repository README claims 99%+ completion on AndroidWorld’s 100+ multi-step tasks; no benchmark protocol, model/version, trial count or independent evaluation is included in the inspected documentation.

Strongest baseline

The project cites Google Research’s AndroidWorld benchmark but does not provide matched competitor runs, full task-level results, model/version details or an external audit in the inspected repository documentation.

Limitations

  • The 99%+ AndroidWorld result is self-reported in the repository; the inspected README does not specify model/version, trial count, per-task scores or benchmark harness details.
  • No independent evaluation or installation/runtime test was performed.
  • Flash omits planning, pre-execution safety checks, checkpoint verification and final reporting; Pro is documented as materially slower per step.
  • The GitHub creation timestamp establishes repository creation metadata, not the exact time at which the project was publicly announced.

What we still don't know

  • The 99%+ AndroidWorld result is unsupported by a reproducible task-level result set or independent evaluation in the inspected repository.
  • The README omits a timing protocol and does not say whether its 3–5s and 15–40s figures include device, model/API and orchestration latency.

Why it matters

A public, permissively licensed Android-control stack could make mobile-agent experimentation and automated UI testing easier to reproduce and integrate. The repository documents useful differences between low-latency reactive control and slower plan/verification, but the claimed benchmark success rate is not independently substantiated by the available materials.
