Evidence

  • Claimed — Anthropic reports that Claude patched discovered bugs and produced Rocq-checked proofs for 239 entry points across 123 OSS-Fuzz libraries. Its stated regime is compiled RISC-V binaries, inputs below 64 MB, single-threaded static execution, a fixed memory budget and modeled Linux responses/layouts.
  • Demonstrated — The linked public Theorem repository currently lists Rocq 9.2.0 proofs for 60 entry points in 25 libraries. Its README defines agreement between plain and sanitizer builds on LPS-valid process inputs, with 2 GiB memory budget for ASan variants and 16 GiB for UBSan; it also says LPS is incomplete and makes unchecked assumptions. This is a smaller public artifact set than Anthropic reports, and the difference is unresolved.
  • Claimed — The public proofs compare plain and sanitizer-instrumented builds: within the statement assumptions, neither reaches an error and both have the same observable behaviors. The repository says these are static riscv64 binaries built with clang 20.1.8 against musl; the release proves no termination/halting statement, covers only code reachable from each entry point, and cannot exclude errors sanitizers do not detect.
  • Not established — The sources do not establish that whole libraries are correct or defect-free, that all security-relevant properties were specified, that Anthropic’s full reported set has been independently checked, or that the approach generalizes beyond the bounded binaries, specifications and LPS model.

Strongest baseline

Conventional fuzzing samples inputs; the public proofs instead establish an all-input theorem within each theorem statement’s LPS model and assumptions. This is a stronger bounded property for sanitizer-detectable behavior, but not whole-library correctness, termination or independent proof validation. No matched human-effort or cost baseline is reported.

Limitations

  • Anthropic participates in the work and is the first-party source for its 239-entry-point/123-library report; this total was not independently reproduced.
  • The linked public repository currently lists 60 entry points in 25 libraries. Its precise public statements use LPS-valid process inputs, with a 2 GiB plain-build memory budget for ASan variants and 16 GiB for UBSan; Anthropic describes a project-wide input bound below 64 MB. The relationship between these scopes and counts is unresolved.
  • The public proofs concern agreement between plain and sanitizer builds for static riscv64 binaries built with clang 20.1.8 against musl, under an incomplete LPS model. They cover code reachable from each fuzz entry point, not whole libraries.
  • The public release proves no halting/termination statement and does not exclude sanitizer-undetected errors such as wrong results or memory leaks. Correctness also depends on the theorem statements and LPS semantics matching the intended property and actual Linux behavior.
  • No independent proof checking, broader replication, model audit or cost measurement was performed in this activation.

What we still don't know

  • No independent party checked a representative sample of the released proofs or reproduced Anthropic's larger 239-entry-point/123-library total in this review.
  • The public theorem statements are bounded to code reachable from one fuzz entry point and agreement between plain and sanitizer builds under LPS assumptions. They do not prove termination, exclude sanitizer-undetected wrong results or memory leaks, or cover behavior omitted by the incomplete Linux model.
  • No labor, compute, proof completion/failure, or maintenance cost comparison establishes the economics or net throughput of this workflow.

Why it matters

If this workflow scales beyond the reported project, lowering the expert effort needed to produce machine-checked proofs could make stronger software security properties practical across widely used libraries. The public artifact set and formal limits make the work inspectable, but current evidence does not establish independent reproduction, general applicability or end-to-end correctness beyond the stated models and fuzz specifications.
