OpenAI releases 722 AI-generated mathematics manuscripts across 372 result families with partial Lean formalization

On October 6, OpenAI published a GitHub collection of mathematical manuscripts generated by an internal frontier model, alongside some Lean formalizations and process details. What actually changed

On October 6, OpenAI published a GitHub collection of mathematical manuscripts generated by an internal frontier model, alongside some Lean formalizations and process details. The repository README reports 722 manuscripts across 372 families and approximately 4,000 attempted problems. OpenAI says not all results are formalized and some unformalized work may contain errors. An independent mathematics advisory group calls the release an important first step, while saying mathematical assessment and human understanding remain to be done.

Claim vs. evidence

  • DEMONSTRATED_PUBLICATION_EVENT — OpenAI published the “Sharing AI progress in mathematics” release and linked public repository on 2026-10-06.
  • CLAIMED_BY_PUBLISHER — The repository README reports 722 manuscripts organized into 372 families, covering results at different verification stages.
  • CLAIMED_BY_PUBLISHER — OpenAI says approximately 4,000 problems were posed and the average result used compute equivalent to roughly three hours of ChatGPT Pro thinking, with stated exceptions.
  • DEMONSTRATED_LIMITATION_DISCLOSURE — The README says some outputs build on earlier model results, not all manuscripts have Lean formalizations, and some unformalized results could contain issues.
  • DEMONSTRATED_INDEPENDENT_RESPONSE — AGMAI described the collection as an important event but said only the mathematical community can assess impact; it characterized public release as the beginning, not completion, of human understanding and did not endorse the process.
  • NOT_ESTABLISHED — The number of novel, correct, independently accepted results; their attribution to the model rather than prior work or human contributions; and any downstream research impact are not established by the inspected release materials.
  • DEMONSTRATED_REPOSITORY_CATALOG — The Lean catalogue describes itself as listing papers with a formalized main result; a read-only count of the unpinned main-branch manifest found 162 source entries. This does not establish that the entries build successfully or have been independently audited.

Strongest baseline

No independent theorem-by-theorem verification or novelty assessment was identified in this targeted release check; the comparison baseline is therefore not established.

The caveat that matters

  • The 722-manuscript and 372-family counts, attempt count and compute estimate are OpenAI repository or company statements, not independently audited measurements.
  • The collection includes results at different verification stages; the README explicitly says not all results are formalized and some unformalized results may have issues.
  • Some manuscripts build on earlier model outputs, and the checked release does not establish theorem-level novelty or exclusive model authorship.
  • AGMAI’s response is an independent statement about release practice and process, not an audit of the mathematical results.
  • No peer-reviewed acceptance, independent proof verification, broad model access, complete attempt-level record or measured downstream use was established in this pass.
  • The 162 manifest entries are a count of catalog records, not independently verified successful builds or accepted theorems. The current main branch was not pinned to a commit, and the catalog count is not directly comparable to 722 manuscripts because families may contain multiple papers.

What remains unknown

  • No independent mathematician assessment or verified error/correction record for individual result families was identified.
  • Model identity, full prompt and attempt-level data are not uniformly disclosed for the collection.
  • Novelty relative to prior literature and earlier model-generated results is unresolved across the large collection.

FCMO Lens

The release creates a large, inspectable corpus for evaluating frontier-model mathematical work and its verification pipeline. Its impact depends on theorem-level novelty, correctness and human assimilation, none of which can be inferred from the manuscript count or the lab announcement.
