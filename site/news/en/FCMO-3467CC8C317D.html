China's cybersecurity standards committee publishes AI Safety Governance Framework 3.0 with an agent lifecycle risk and control model

On 2026-09-14, China’s National Technical Committee 260 on Cybersecurity (TC260), under CAC guidance, published the Chinese-language AI Safety Governance Framework 3.0. Its 136-page document classifies risks and recommends mitigations across AI-agent design, installation/deployment, instruction input, reasoning/planning, tool execution, memory, output and shutdown. It identifies prompt injection, context overflow, tool poisoning and overreach, memory contamination/theft, behavior escape, and residual credentials/processes after shutdown. Recommended controls include pre-deployment risk assessment, staged increases in access and autonomy, unique agent identity and least privilege, revocable credentials, human approval and ability to interrupt high-risk operations, fail-closed approval handling, runtime guardrails, and memory isolation. Comparison with the official 2025 Framework 2.0 shows that 2.0 already discussed autonomous agent planning and privilege/file-access risks, but did not have a dedicated agentic-AI lifecycle appendix. Version 3.0 adds that appendix and separately maps agent identity/permission, planning, tool-execution, memory, embodied and multi-agent risks. This documents a change in framework scope; neither publication establishes binding law, broad adoption or control effectiveness.

What actually changed

On 2026-09-14, China’s National Technical Committee 260 on Cybersecurity (TC260), under CAC guidance, published the Chinese-language AI Safety Governance Framework 3.0. Its 136-page document classifies risks and recommends mitigations across AI-agent design, installation/deployment, instruction input, reasoning/planning, tool execution, memory, output and shutdown. It identifies prompt injection, context overflow, tool poisoning and overreach, memory contamination/theft, behavior escape, and residual credentials/processes after shutdown. Recommended controls include pre-deployment risk assessment, staged increases in access and autonomy, unique agent identity and least privilege, revocable credentials, human approval and ability to interrupt high-risk operations, fail-closed approval handling, runtime guardrails, and memory isolation. Comparison with the official 2025 Framework 2.0 shows that 2.0 already discussed autonomous agent planning and privilege/file-access risks, but did not have a dedicated agentic-AI lifecycle appendix. Version 3.0 adds that appendix and separately maps agent identity/permission, planning, tool-execution, memory, embodied and multi-agent risks. This documents a change in framework scope; neither publication establishes binding law, broad adoption or control effectiveness.

Strongest baseline

The official 2025 Framework 2.0 already mentions autonomous agent planning, access to files/permissions/interfaces/tools, privilege abuse, application risk grading and an agent glossary definition. Framework 3.0 adds a dedicated Agentic AI risk-management appendix and explicit categories for identity/permission, planning, invocation/execution, memory, embodied and multi-agent risks.

The caveat that matters

  • The release describes a technical framework; the inspected pages do not establish that its recommendations are binding legal requirements.
  • No organizational adoption, enforcement, compliance cost, incident reduction or safety effectiveness evidence was inspected.
  • The framework's risk descriptions are policy statements and anticipated risks, not independent empirical prevalence measurements.
  • The version comparison is a targeted text-level comparison of selected agent, risk-classification and appendix sections, not a clause-by-clause legal or bilingual translation audit.

What remains unknown

  • Version 3.0's exact additions and deletions relative to the full version 2.0 text have not been established.
  • No independent evidence shows how many providers or deployers adopted the recommendations or whether the controls reduced agent-security incidents.
  • The legal or compliance status of Framework 3.0 is not stated in the inspected release notice or framework passages.

FCMO Lens

The framework translates agent security concerns into a lifecycle control set spanning identity, permissions, tool supply chains, untrusted inputs, long-term memory, human intervention and shutdown. If implemented, these recommendations could change agent platform architecture and deployment review. The consequence is bounded because this is a guidance document and no adoption, enforcement, or control effectiveness was established.
