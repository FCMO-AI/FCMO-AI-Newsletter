What changed

A September 12 journal paper evaluates GPT-5.4 and DeepSeek v4 Flash on 130 obfuscated AnB/AnBx protocols covering 388 security goals, with three runs per configuration and formal-verifier references. The authors report a chat-versus-reasoning trade-off: chat modes recall more attacks but generate many false alarms, while reasoning raises precision and misses more attacks. On their imbalanced goal set, both chat configurations score below a 77.1% always-secure accuracy baseline; agreement authentication goals remain difficult, and self-reported confidence is poorly calibrated. The paper recommends pre-screening only, with formal confirmation. These are author-reported results; the journal article and public artifact were not independently reproduced in this review.

Evidence

  • Claimed — The authors report three runs per configuration on 130 type-aware-obfuscated AnB/AnBx protocols covering 388 security goals, comparing GPT-5.4 and DeepSeek v4 Flash chat and reasoning settings against ProVerif and OFMC verdicts.
  • Claimed — The authors report chat recall of 72.7% for GPT and 69.3% for DeepSeek with precision below 28%; reasoning raises reported precision to 66.5% for GPT and 45.4% for DeepSeek while recall falls to roughly 55%.
  • Claimed — The published paper reports that the goal set contains 89 vulnerable and 299 secure goals, so a predictor that always answers secure obtains 77.1% accuracy; neither chat configuration reaches that accuracy. The authors emphasize recall rather than accuracy for this imbalanced screening task.
  • Claimed — The authors report persistent difficulty with injective and non-injective agreement attacks, unstable verdicts across repeated runs, and high self-reported confidence that does not reliably distinguish correct from incorrect answers. They recommend pre-screening only and formal confirmation.
  • Demonstrated limitation — These are author-reported results, not an independent reproduction. The reviewed publisher-indexed article and repository README identify released code and experiment artifacts, but the full tables, appendices and data were not audited here.

Strongest baseline

Always-secure classification yields 77.1% accuracy on the study's imbalanced goal set. Formal-verifier outputs are used as reference labels. Accuracy baseline and attack-recall objective answer different questions and must not be conflated.

Limitations

  • Results are reported by the authors and were not independently reproduced in this review.
  • Only GPT-5.4 and DeepSeek v4 Flash, one protocol notation, one fixed zero-shot prompt and 130 protocols are covered; transfer is unknown.
  • The goal set is imbalanced (89 vulnerable, 299 secure); the 77.1% always-secure accuracy baseline is not a substitute for recall or safety assessment.
  • The publisher page was rate-limited in this review; full methods tables, appendices, data rows, confidence intervals and exact protocol-level labels were not inspected.
  • Public repository availability was confirmed from its README, but no commit-pinned artifact or data audit was performed.
  • Reported weaknesses are specific to direct binary LLM verdicts in this experimental regime and do not establish a general capability ceiling for all models or prompt designs.

What we still don't know

  • The public experiment repository was identified but its commit-pinned inputs, outputs, goal labels and analysis code were not audited or independently re-scored.
  • The full journal article and appendices could not be opened directly because the publisher returned HTTP 429; the arXiv HTML conversion stops before the methods/results sections, so a complete version-diff was not performed.

Why it matters

Security protocol analysis is safety-relevant and has formal verification tools with explicit semantics. The reported precision/recall trade-off and missed authentication attacks bound how these tested LLM configurations could be used: a fast language-model pass may help prioritize work, but cannot replace formal verification or justify skipping it. The result is limited to two providers, one notation family and one zero-shot prompt.
