What changed

Mistral introduced Managed Agents and its Python Agents SDK in public preview on 5 November. The documented service stores sessions for deployed agents, supports background execution and approval waits, and says a worker crash resumes from its last completed model or tool call. Teams can run the same agent in-process, self-host the harness or deploy a Mistral-managed worker. The documentation lists defaults of 24 hours per session, four idle hours and one hour for an approval wait, with higher limits configurable. These are provider-described capabilities; no independent service test or production outcome was verified.

Evidence

  • Demonstrated — Mistral published Managed Agents documentation and marked the Agents SDK and managed service as public preview on 5 November 2026.
  • Claimed — Mistral’s documentation describes durable sessions that can continue after the client app exits, resume after a worker crash from the last completed model or tool call, and wait for approval while the app is closed. It states that default session limits are 24 hours total, 4 hours idle, and one hour for an approval wait; higher session limits can be configured.
  • Claimed — Mistral documents a Python Agents SDK with three run modes: in-process development, self-hosted workers through agents serve, and Mistral-managed workers through agents deploy. In the deployed modes, Mistral stores session state; the harness and tool execution may run on the user’s servers or Mistral infrastructure.
  • Not established — The announcement and documentation do not independently establish crash-recovery reliability, availability, isolation, security, production adoption, or improved agent task outcomes.

Strongest baseline

The provider documents in-process execution as the development mode: unlike deployed modes, its session lives in the application process and ends with it. No matched operational comparison was run.

Limitations

  • Managed Agents and the SDK are explicitly in public preview, and their API, behavior and limits may change.
  • Crash recovery and approval-wait behavior are provider-documented but not independently tested here.
  • The documentation’s 24-hour total, 4-hour idle and one-hour approval-wait defaults can be raised; actual configured limits and account availability were not checked.
  • No independent evidence establishes security, uptime, customer adoption or improved task success.

What we still don't know

  • Durable resume, session persistence, approval timeout and worker behavior have not been independently exercised.
  • The preview documentation does not establish service availability, production reliability, workload limits beyond stated defaults or comparative operational cost.

Why it matters

Long-running tool agents need durable state, recovery boundaries and human approvals that remain available when a client process stops. Mistral’s public-preview documentation describes these as runtime features of one SDK across self-hosted and hosted modes. If they work as specified, they could reduce custom orchestration work; reliability, security and task-level benefits still need independent testing.
