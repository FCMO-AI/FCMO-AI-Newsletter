A prompt-complexity study finds that coding-reliability breakpoints depend on task and prompt composition

In an analysis of 5,000 coding prompts and 21 models, the authors report a pooled prompt-complexity breakpoint associated with higher code correctness. The estimated breakpoint and gap change substantially after controlling for task type and prompt-construction frame, and model-specific changes go in both directions. The results are author-reported, observational benchmark findings; they do not establish a universal threshold or causal effect.

What actually changed

In an analysis of 5,000 coding prompts and 21 models, the authors report a pooled prompt-complexity breakpoint associated with higher code correctness. The estimated breakpoint and gap change substantially after controlling for task type and prompt-construction frame, and model-specific changes go in both directions. The results are author-reported, observational benchmark findings; they do not establish a universal threshold or causal effect.

Claim vs. evidence

  • CLAIMED — The authors report a pooled prompt-complexity breakpoint of 13.75 with correctness 79.9% below/at versus 87.6% above; task-type controls shift the breakpoint to 10.75 and reduce the gap to 2.1 percentage points, while a post-hoc construction-frame control shifts it to 8.5 and reverses the raw gap to -3.5 points.
  • CLAIMED — The authors report 16 upward and 5 downward model-specific changes and state that no single complexity cutoff generalizes across models.
  • CLAIMED — The reported analysis scores 5,000 coding prompts on six dimensions using four LLM raters and evaluates 21 models, totaling 105,000 generations; it is an observational benchmark analysis rather than evidence of a causal universal reliability threshold.

Strongest baseline

The paper compares pooled estimates with task-type fixed effects, a post-hoc prompt-construction-frame control, model-specific changes and an audit-clean extension. It does not establish a causal intervention or compare against a separately randomized prompt-composition design.

The caveat that matters

  • The findings are observational benchmark associations; they do not establish that increasing prompt complexity causes correctness to improve.
  • The pooled breakpoint is sensitive to task-type and prompt-construction controls, so none should be treated as a universal cutoff.
  • Four LLM raters produced moderate and rater-dependent agreement with human judgments; scoring remains partly judgment-based.
  • The audit-clean extension adds 365 prompts but only 14 prompts above complexity score 16, limiting evidence in that range.
  • The analysis uses one prompt corpus and its task/construction mix; transfer to repository coding, production software or other prompt populations is unknown.
  • All findings are author-reported; the research desk did not independently reproduce prompt scoring, generations or regression analyses.
  • The pooled positive above/below breakpoint gap is reduced under task-type controls and reverses under the post-hoc construction-frame control; this is an internal sensitivity result, not independent replication.

What remains unknown

  • The source analysis, prompt scores and breakpoint sensitivity have not been independently reproduced; transfer beyond the evaluated prompt mix is unknown.

FCMO Lens

If replicated, the sensitivity to task and prompt composition matters for benchmark design: aggregate prompt-complexity curves can suggest a reliability threshold that shifts or reverses under plausible controls. Evaluations should stratify tasks and construction frames and report model-specific responses before using a pooled breakpoint to guide engineering decisions.
