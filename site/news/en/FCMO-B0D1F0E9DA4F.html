What changed

An Ant Group-authored arXiv paper introduces GameASG-Bench, a benchmark of 47 browser-native game-generation tasks with predeclared evaluation interfaces, static checks and browser-executed behavioral checks. Across nine agent stacks, the authors report a highest mean L2 check pass rate of 93.2% but a highest strict task success rate of 55.3% (26/47), where strict success requires delivery and every required check to pass. The result shows that high average check rates can coexist with incomplete task compliance in this benchmark. Each task-configuration pair was run once; these paper-reported results do not establish performance across broader software tasks or independent replication.

Evidence

  • Demonstrated — The arXiv v1 paper and linked public repository define GameASG-Bench as 47 browser-native game-generation tasks with a predeclared evaluation interface, 336 static L1 checks and 885 browser-executed L2 checks; the authors report that each reference implementation passed all L1 and applicable L2 prerequisite/core checks.
  • Claimed — Across nine agent stacks on the 47 tasks, the authors report a highest mean L2 check pass rate of 93.2% and a highest strict task success rate of 55.3% (26/47). Strict task success requires valid delivery, completed evaluation and passing all L1 checks and applicable L2 prerequisite and core checks.
  • Claimed — In the paper's DeepSeek-V4-Flash comparisons, full tool access yields 18 strict task successes versus 6–9 with limited tool access, and the rate over all planned tasks rises from 7/47 to 18/47 as the nominal turn budget increases from 30 to 120. These are single-run benchmark results, not estimates of run-to-run variance.
  • Not established — The benchmark does not establish general autonomous software-generation success outside its browser-game task set, nor does one run per task-configuration establish variance or independent replication.

Strongest baseline

Nine tested model/harness stacks use the same 47 task packages and evaluation protocol; within-stack tool-access, turn-budget, reasoning-effort and harness comparisons are reported.

Limitations

  • The primary evidence is an author-reported arXiv v1 paper and linked author repository; no independent replication was performed in this review.
  • The 47 tasks are browser-native games with self-contained index.html delivery, not a representative sample of software engineering tasks.
  • Each task-configuration pair is run once, so the study does not estimate run-to-run variance.
  • The strict-success and check-pass metrics differ by construction: strict success requires every check to pass, while mean check rates aggregate partial compliance. Their gap is informative but not a direct general measure of agent capability.

What we still don't know

  • The benchmark results have not been independently reproduced. The paper says each task-configuration pair was run once, so run-to-run variation is not estimated.
  • The evidence is limited to 47 self-contained browser-native game tasks, the tested models/harnesses and the authors' evaluation interface; transfer to general software generation remains unknown.

Why it matters

If the gap generalizes, average pass rates can make agent-generated software appear more complete than it is under all specified requirements. The benchmark makes that distinction measurable, but its single-run browser-game results need replication and transfer tests before broader conclusions.
