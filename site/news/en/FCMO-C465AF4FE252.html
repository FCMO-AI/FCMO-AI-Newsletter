Google Home MCP exposes real device-state and control tools to AI clients in early access

Google Home’s early-access MCP server connects compatible AI clients to real smart-home data and actions. Google’s developer documentation lists tools for discovering homes and devices, reading live state and history, and issuing device-control commands. It warns that an agent connected to a real home can control devices, describes rate limits and sensitive-action protections such as blocking door unlocking, and requires client permission before execution. Access requires a Premium Advanced subscription and approved project; automation creation was not yet supported on the page updated September 21. These are documented product capabilities and safeguards, not an independent test of enforcement or deployed use.

Claim vs. evidence

  • CLAIMED — Google documentation describes an early-access Home MCP server that lets compatible AI clients inspect home structures, device resources, live device states and historical events, and issue parameterized device-control actions.
  • CLAIMED — Google documentation warns that connecting a real home allows an AI agent to control devices; it lists rate limits and protections including prohibiting sensitive actions such as unlocking doors, and says tool execution permission is granted through the client.
  • DEMONSTRATED — The inspected Google developer page labels Home MCP Early Access, says a Google Home Premium Advanced subscription and project approval are prerequisites, and records that automation creation was not yet supported as of its 2026-09-21 update.

Strongest baseline

Google’s documentation describes ordinary Home API access and the MCP proxy. No matched evaluation against direct API integrations or competing home-control agents was found.

The caveat that matters

  • This record covers documented product functionality, not measured agent capability or real-world deployment outcomes.
  • Google warns users that agents connected to real homes can behave unexpectedly; user review and revocation remain part of the documented model.

What remains unknown

  • No independent test confirms that the stated sensitive-action restrictions and user-consent controls are enforced across tools and client implementations.
  • The early-access documentation does not establish deployment scale, reliability or household-level effects.

FCMO Lens

This is a concrete path from general-purpose agents to physical device control in consumer environments. The practical boundary depends on the tool schema, authorization and server-side action restrictions, so the documented safeguards and their tested enforcement matter more than the MCP label alone.
