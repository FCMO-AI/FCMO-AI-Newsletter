发生了什么变化

一篇 九月20日的预印本介绍 BabelFlow，这是一套跨语言改造代理基准的流程，旨在保留指令、工具、环境与评测器之间的关联；论文还发布了 BabelArena，包含 23 种语言的 16,146 个实例。在一项针对 40 个任务的中文消融中，作者报告相较独立翻译，损坏的引用和观察到的行为不匹配更少，但 token 成本更高。对五个模型的评估报告称，低资源语言组的任务成功率和语言一致性较低，样例中的工具使用/控制流错误类型也不同，输入 token 使用量更高。这些是论文报告的结果；翻译有效性、独立复现及结果能否推广仍待验证。

证据

  • 已展示 — arXiv v1 论文将 BabelArena 描述为包含 16,146 个实例的基准，源自 702 个规范任务、四类基准、13 个领域和 23 种语言；各基准组件均经过适配，以保留任务的可执行结构。
  • 声称 — 在一项包含 40 个中文适配任务的消融中，作者报告 BabelFlow 将引用损坏率从独立翻译的 20.0% 降至 2.5%，将观察到的行为不匹配从 5.0% 降至 0%；该流程使用的翻译 token 是基线的 3.35 倍。
  • 声称 — 论文报告，在五个受测模型中，低资源语言组的平均任务成功率和语言一致性均低于高资源语言组。在 VitaBench 抽样失败案例中，泰语和泰米尔语的工具使用及控制流错误比例高于英语和中文；匹配任务上的低资源语言 VitaBench 轨迹使用的输入 token 是英语轨迹的 1.69–2.06 倍，而交互轮数相近。
  • 尚未确立 — 该论文尚未证明翻译后的基准保留了每个源任务的语义或文化效度，也未证明所测差异可推广到其他模型、任务或部署人群；本次未检查独立评估。

最强基线

对构建缺陷，BabelFlow 与同一批 40 个源任务上的独立字段翻译及规范化翻译比较。模型评估保留各源基准的评分流程，但没有为每种语言和模型组合提供统一的单语言匹配对照。

局限

  • 单一团队预印本；未检查独立复现。
  • 仅对 40 项中文任务开展翻译流程消融；其 token 成本为独立翻译的 3.35 倍。
  • 每种语言抽查 200 段文本；中低资源语言样例由 GPT-5.6-Sol 而非人工语言专家评分。
  • 五个模型和四类基准不足以证明广泛部署表现；部分错误分析使用抽样轨迹。

尚不清楚的问题

  • 没有独立团队复现 BabelFlow 构建对比，也没有复现 BabelArena 的五模型评估。
  • 质量保障每种语言抽查 200 段文本；高资源语言由专家评估翻译质量，中低资源语言则由 GPT-5.6-Sol 评分。样例以外的等价性和文化有效性未知。
  • 五模型结果和错误分析覆盖四类基准及部分样例，尚未证明对广泛模型、任务或部署场景的覆盖。

为何重要

只翻译用户指令可能使工具、数据库、解析器和评分规则彼此不一致，因此多语言代理测试需要覆盖可执行的完整流程。BabelArena 论文报告低资源语言运行在任务成功率、工具/控制流错误和输入 token 使用量上的差异。这些结果可能影响评测设计和推理成本估算，但目前来自单一团队对部分基准和语言的研究。
