一篇预印本报告了三种 AI 代理协议中可测量的握手开销

一篇 arXiv 预印本使用官方 Python SDK，分阶段测量 MCP、A2A 与 ACP 的代理启动开销。对于 MCP 2026-07-28 版本，官方规范已移除 initialize/initialized 交换和协议会话；论文将“握手”操作性地定义为从能力发现到任务就绪的过程，其中包括 server/discover。论文称每个测试单元测量 50 次；在模拟 50 ms 应用层往返时延时，冷启动中位数分别为旧版 MCP 230 ms、新版 MCP 122 ms、A2A 61.0 ms、ACP 62.1 ms。论文还报告每项能力元数据开销为 24–107 个 token。这些是作者在精简回声代理环境中报告的结果，尚非独立复现或生产工作负载测量。论文 HTML 称实验于 2026 年八月 10 日进行，而链接仓库 README 称论文测量于九月 30 日完成；arXiv v1 提交记录为 12 日，但 cs.AI 新提交列表在 十月 23 日才列出该条目。时间线和原始数据绑定仍未解决。

发生了什么变化

一篇 arXiv 预印本使用官方 Python SDK，分阶段测量 MCP、A2A 与 ACP 的代理启动开销。对于 MCP 2026-07-28 版本，官方规范已移除 initialize/initialized 交换和协议会话；论文将“握手”操作性地定义为从能力发现到任务就绪的过程，其中包括 server/discover。论文称每个测试单元测量 50 次；在模拟 50 ms 应用层往返时延时，冷启动中位数分别为旧版 MCP 230 ms、新版 MCP 122 ms、A2A 61.0 ms、ACP 62.1 ms。论文还报告每项能力元数据开销为 24–107 个 token。这些是作者在精简回声代理环境中报告的结果，尚非独立复现或生产工作负载测量。论文 HTML 称实验于 2026 年八月 10 日进行，而链接仓库 README 称论文测量于九月 30 日完成；arXiv v1 提交记录为 12 日，但 cs.AI 新提交列表在 十月 23 日才列出该条目。时间线和原始数据绑定仍未解决。

证据

  • 声称 — 这篇预印本按阶段比较了 MCP（旧版和新版）、A2A 与 ACP 的握手过程，使用各协议官方 Python SDK；每个协议、场景和网络条件组合测量 50 次，并采用精简的回声代理。
  • 声称 — 在用户态中继模拟的 50 ms 应用层往返时延下，作者报告的冷启动中位数为：旧版 MCP 230 ms、新版 MCP 122 ms、A2A 61.0 ms、ACP 62.1 ms。论文说明未计入 TCP 和 TLS 建连时间；该中继也没有按数据包模拟网络。
  • 声称 — 作者报告，当由语言模型驱动的发起方读取对端元数据时，每项公布的能力会带来 24–107 个 token 的开销；按其计数方法，200 项能力约占 200,000-token 上下文窗口的 11%。
  • 有争议 — 相关材料对实验时间存在冲突：arXiv v1 HTML 称实验于 2026 年八月 10 日进行，v1 提交记录为 八月 12 日；链接仓库的 README 则称论文中的测量于 2026 年九月 30 日完成。cs.AI 新提交列表在 2026 年十月 23 日列出了同一 arXiv 编号。
  • 尚未确立 — 本次审查没有确认独立复现、生产环境中的时延或成本影响，也没有确认包含 TCP/TLS 建连的真实网络表现。
  • 推断 — 对于 MCP 2026-07-28 版本，官方规范移除了 initialize/initialized 交换和协议会话，加入 server/discover，并允许缓存部分列表/读取结果。因此，论文定义下的新版 MCP 冷启动测量涵盖从能力发现到就绪的过程，而非已取消的会话握手。

最强基线

在论文模拟的 50 ms 应用层往返时延条件下，作者比较了旧版 MCP、新版 MCP、A2A 和 ACP 的冷启动中位数。该比较由作者报告，使用非数据包级中继且未计入 TCP/TLS 建连；没有独立或生产环境基线。

局限

  • 这些结果是单篇预印本的报告，本次没有独立复现。
  • 测试使用精简回声代理和特定 SDK/规范版本，并非有代表性的生产代理。
  • 50 ms 条件是用户态应用层延迟模拟；未计入 TCP/TLS，也不能准确模拟数据包分段。
  • token 估算取决于所用分词器和假定的模型价格。
  • arXiv 元数据与链接仓库 README 的实验时间存在冲突。
  • 论文把“握手”用作任务就绪度量；官方 MCP 2026-07-28 规范移除了 initialize/initialized 交换和协议会话，因此新版 MCP 的结果指能力发现/列表查询路径，而非已取消的交换。
  • arXiv v1 HTML 将实验日期标为 2026 年八月 10 日，v1 提交历史标为 八月 12 日；链接仓库 README 则称论文中的测量于 九月 30 日（2026 年）完成。cs.AI 新提交列表在 十月 23 日（2026 年）显示了 arXiv:2610.30151。这些日期不足以确定实际测量对应的产物版本。

为何重要

对于远程或持续时间很短的代理交互，握手往返和能力元数据可能在任务开始前消耗时延和上下文。该论文提出一项范围明确、值得跟踪的测量结果；但其精简代理、用户态延迟模拟、未计入 TCP/TLS，以及尚未解决的实验时间线，限制了结果向真实部署的外推。
