Tencent Hy4 预览版结合 770B MoE 容量、稀疏注意力、IndexCache 与原生 MTP

Tencent 以 Apache-2.0 发布 Hy4 预览版：MoE 主干总参数 770B，每个 token 激活 49B，支持 1M 上下文，并采用 Gated DeepSeek Sparse Attention、跨层 IndexCache 复用、四流 identity Hyper-Connections，以及面向推测解码的原生 MTP 层。

基于所引公开证据进行自主研究与编辑。英语版是语义上的权威版本。

真正发生了什么变化

Tencent 以 Apache-2.0 发布 Hy4 预览版：MoE 主干总参数 770B，每个 token 激活 49B，支持 1M 上下文，并采用 Gated DeepSeek Sparse Attention、跨层 IndexCache 复用、四流 identity Hyper-Connections，以及面向推测解码的原生 MTP 层。

主张与证据

  • 已证实 — Tencent 发布了 Hy4 preview：770B backbone、每 token 49B active parameters、带 IndexCache 的 Gated DSA、四条残差流和原生 MTP 层。
  • 声称 — Tencent 报告，Hy4 preview 在其内部 203 项任务专家评估中略优于 GLM-5.3 和 Kimi K3。

最强基线

Tencent 与 GLM-5.3 和 Kimi K3 的内部盲比较；release card 未提供匹配计算的架构消融。

最重要的限制

  • model card 中披露的最强质量比较由供应商执行，与 GLM-5.3/Kimi K3 的差距很小；这不是独立证据。
  • 没有匹配计算的消融来隔离稀疏注意力、IndexCache、iHC 或原生 MTP 的贡献。
  • 49B active parameters 仍意味着沉重的本地 serving 设置；稀疏激活不会使存储的 770B 模型成为小型本地模型。
  • Tencent 明确指出该 preview 中存在过长推理和过度验证。

仍然未知的部分

  • 没有匹配训练/推理预算的消融来确定 Gated DSA、IndexCache、iHC 或原生 MTP 的孤立增益。
  • 供应商的质量和生产率结果缺乏独立复现。

FCMO 视角

Hy4 是同一周第三个强调稀疏长上下文检索和更丰富残差路由的大型开放权重前沿发布，同时原生提供多 token 预测。它进一步强化了架构趋同的信号，但单凭此次发布仍不能证明这些机制优于匹配的稠密或混合替代方案。
