真正发生了什么变化

Adikari 和 Herath 在 992 道改写为 Java Spring Boot 方法的 Project Euler 题目上，评估了 三个经济型模型的 八种模型、编程代理工具与提示格式组合。他们报告称，生成结果几乎都符合所需的方法签名，且执行了 7,936 次请求；但返回答案中只有 12.9% 正确，38.4% 的生成方法没有计算自己返回的值。这是一项单次生成、作者报告的有限算法语料评估，并未测量企业代码或已部署助手的错误率。

主张与证据

  • 声称 — 作者报告称，生成的 Java 方法符合规定签名，但 38.4% 没有计算其返回值；在本次评估中，返回答案仅有 12.9% 正确。
  • 声称 — 结果来自 三个经济型模型、四种模型/编程工具组合和 两种提示布局，在 992 道 Project Euler 题目上以单次 Java Spring Boot 代码生成方式完成。
  • 声称 — 作者报告称，语义合规度与正确性指标呈反向关联，但明确提醒两者分母不同，相关性不能证明尝试计算更多会导致准确率下降。

最强基线

论文评估 Gemini Flash 3 与 Cursor、GPT-5.4 mini 与 Cursor，以及 Claude Haiku 4.5 分别搭配 Cursor 和 Claude Code；这 四种模型/工具组合各采用 两种提示布局。论文在同一批方法上比较结构/策略分类与运行正确性；本次所检研究没有单独的人类代码或前沿模型对照组。

最重要的限制

  • 实验将 Project Euler 数值题目改写为 Java Spring Boot 方法；它没有测量企业应用开发、仓库级任务或已部署编程助手的失效率。
  • 每个任务/配置只生成一次，因此所报比例无法估计不同采样之间的变化，也不能确定模型稳定的失效概率。
  • 语料可能存在污染风险：作者指出，早期 Project Euler 题目在网上被广泛讨论，并报告许多字面匹配集中在早期题目。
  • 论文报告各配置生成代码的覆盖率不完整，表 II 中范围为 80.1%–100.0%；缺失方法和运行错误会影响分母。
  • 所报负相关不能证明更好的语义合规会导致更低准确率。论文解释分母和题目难度不同；GPT-5.4 mini 最强的条件正确率集中在较容易的早期题号。
  • 论文采用语法/静态分类，测试框架也只覆盖指定输出模式；没有评估复杂语义、人工审查、迭代修复、仓库上下文或更强的对抗性测试。
  • 所有结果均由作者报告；研究团队未检查原始生成工件、运行作者或公开代码，也未独立复现评测。

仍然未知的部分

  • 研究的方法分类、生成代码数量和正确性结果尚未经过独立复现；本次审查未找到作者代码工件。
  • 在仓库级、企业级或迭代代码生成任务中是否也存在所测结构/功能差距仍未知；当前评估采用单次 Project Euler 到 Spring 的生成方式。

FCMO 视角

该研究在同一份生成代码上同时检查结构和实际执行结果，并报告有效签名可能与编造或错误输出并存。如果这一有限结果能够推广，仅检查代码外形和回答率可能会漏掉代码生成评估中的严重失效。论文没有证明这些问题在其特定任务、模型和单次生成设置之外的发生率。
