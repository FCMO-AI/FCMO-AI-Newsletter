联合子空间稀疏注意力在作者测试中提升长上下文解码速度

十月13日发布的预印本介绍了联合子空间稀疏注意力（JSSA），这是一种无需训练的逐 token 稀疏注意力方法，将共享的查询—键评分子空间与免聚集索引注意力结合起来。作者在单张 NVIDIA B200 上，以 128K 上下文和 2,048 个选定 KV token 进行测试，报告称：Qwen3-8B 的解码吞吐量最高为全量 KV 注意力的 1.51×，Gemma4-26B-A4B-It 为 1.88×，GLM-4.7-Flash 为 6.43×。作者称，在所测任务中，其准确率接近全量 KV 注意力，并公开了实现和基准脚本。这些结果来自论文报告；本研究团队未进行复现。

发生了什么变化

十月13日发布的预印本介绍了联合子空间稀疏注意力（JSSA），这是一种无需训练的逐 token 稀疏注意力方法，将共享的查询—键评分子空间与免聚集索引注意力结合起来。作者在单张 NVIDIA B200 上，以 128K 上下文和 2,048 个选定 KV token 进行测试，报告称：Qwen3-8B 的解码吞吐量最高为全量 KV 注意力的 1.51×，Gemma4-26B-A4B-It 为 1.88×，GLM-4.7-Flash 为 6.43×。作者称，在所测任务中，其准确率接近全量 KV 注意力，并公开了实现和基准脚本。这些结果来自论文报告；本研究团队未进行复现。

证据

  • 声称 — 作者提出 JSSA：一种无需训练的逐 token 稀疏注意力方法，在共享的低维查询—键子空间中对 token 评分，并通过免聚集索引注意力支持 GQA 中各 KV 头分别选择 token。
  • 声称 — 在单张 NVIDIA B200 上，以 128K 上下文和 2,048 个 KV token 为预算，作者报告其解码吞吐量最高可达全量 KV 注意力的 1.51×（Qwen3-8B）、1.88×（Gemma4-26B-A4B-It）和 6.43×（GLM-4.7-Flash）；Gemma4 测试仅对全局注意力层使用稀疏化。
  • 声称 — 论文称，在所测长上下文和推理任务中，JSSA 的准确率接近全量 KV 注意力；在约 700B 参数规模下，作者报告其吞吐量达到原生 DSA 的 96.1–99.2%，测试使用八张 B200 GPU，并存在模型与检查点可比性限制。
  • 已证实 — 作者公开仓库包含 vLLM 补丁、校准代码、基准测试脚本、论文与代码对应关系及配置说明。这说明相关工件可获取，但不代表有人独立验证了所报告的结果。
  • 尚未确立 — 所报告的速度提升尚未经过独立复现，也没有证明部署环境下的质量、吞吐量、成本或可靠性得到普遍改善。

最强基线

论文在所述配置中将该方法与全量 KV 注意力及若干稀疏注意力基线比较。结果由作者测试得出，本研究团队未进行独立的同条件对照。

局限

  • 所有质量和性能数值均由作者报告；本研究团队未执行代码，也未独立复现测量结果。
  • 1.51×、1.88×和 6.43×是单张 B200、128K 上下文和 2,048-token KV 预算下的最高值；最大值针对 GLM-4.7-Flash，并依赖 MLA/FlashMLA 稀疏执行。
  • 对 Gemma4-26B-A4B-It，仅对全局注意力层进行了稀疏化；局部滑动窗口层仍使用密集注意力。
  • 附录 A.7 说明测试先进行一次预热，再测量三次，每次生成 128 个 token；吞吐量测量不包括模型载入、校准、kernel 编译和预热。
  • 约 700B 规模的比较使用八张 B200 GPU，并存在检查点可比性限制；论文没有 GLM-5.2 对应的全量注意力检查点。
  • 论文和代码仓库未证明部署环境中的成本、可靠性、服务质量、能耗或独立复现结果。

尚不清楚的问题

  • 本次审查未独立复现论文中的速度、质量或长上下文解码吞吐量结果。
  • 吞吐量来自较短的测量流程，并受注意力架构、上下文长度、批量大小、硬件、缓存格式、校准和稀疏 token 预算影响；部署中的成本和服务质量影响尚未测量。
  • 约 700B 规模的比较没有 GLM-5.2 全量注意力检查点；DeepSeek 的比较则使用了不同检查点和训练状态下的原生 DSA，因而无法单独识别架构本身的因果效果。

为何重要

长上下文解码可能受 KV 缓存内存流量限制。如果这些结果能够推广，无需训练且公开实现的稀疏注意力方法可能改变多种注意力架构的服务设计选择。最大提升针对的是 128K 上下文、2,048-token 预算下的 GLM-4.7-Flash；这并不能证明服务吞吐量普遍提升 6.43×，也不能证明部署成本下降。
