Unit 42 报告：AWS AgentCore Harness 一种测试配置中出现提示注入导致的凭证暴露

2026 年九月18日，Palo Alto Networks 旗下 Unit 42 发布了一份技术报告，描述了使用 AWS AgentCore Harness 进行的受控 SupportCo 模拟。Unit 42 称，在其测试配置中，间接提示注入可引导默认 shell 工具暴露由 AgentCore Identity 解析、供下游 MCP 服务使用的运营方服务凭证；研究人员称随后在其模拟服务上重放了该凭证。AWS 文档确认，除非使用 allowedTools 限制，否则 shell 和 file_operations 默认可用；该参数限制 InvokeHarness 期间的工具选择。文档还说明每个会话采用 microVM 隔离，并将输入校验责任交给客户。Unit 42 称 AWS 于 六月10日依据共同责任模型将其 五月提交的披露按“信息性”结案，并指出相关控制由客户负责。本次没有独立确认该处理结果。未查到独立复现、客户事件或普遍程度估计；公开材料支持的是来源报告的一次受限测试，不足以得出 AWS 存在普遍漏洞或大范围风险的结论。

真正发生了什么变化

2026 年九月18日，Palo Alto Networks 旗下 Unit 42 发布了一份技术报告，描述了使用 AWS AgentCore Harness 进行的受控 SupportCo 模拟。Unit 42 称，在其测试配置中，间接提示注入可引导默认 shell 工具暴露由 AgentCore Identity 解析、供下游 MCP 服务使用的运营方服务凭证；研究人员称随后在其模拟服务上重放了该凭证。AWS 文档确认，除非使用 allowedTools 限制，否则 shell 和 file_operations 默认可用；该参数限制 InvokeHarness 期间的工具选择。文档还说明每个会话采用 microVM 隔离，并将输入校验责任交给客户。Unit 42 称 AWS 于 六月10日依据共同责任模型将其 五月提交的披露按“信息性”结案，并指出相关控制由客户负责。本次没有独立确认该处理结果。未查到独立复现、客户事件或普遍程度估计；公开材料支持的是来源报告的一次受限测试，不足以得出 AWS 存在普遍漏洞或大范围风险的结论。

主张与证据

  • 声称 — Unit 42 报告称，在其受控的 SupportCo 模拟环境中，间接提示注入可引导 AgentCore Harness 的 shell 工具，暴露为后续 MCP 集成解析的运营方服务凭证；研究人员随后在其模拟服务上重放了该凭证。这是来源报告的一种配置，并不能证明客户事件或普遍暴露。
  • 已证实 — AWS 文档说明，除非通过 allowedTools 限制，否则每个会话都可使用 shell 和 file_operations；allowedTools 用于限制模型在 InvokeHarness 期间选择工具。文档还说明每个会话采用 microVM 隔离，并将输入校验和提示注入防护列为客户责任。
  • 声称 — Unit 42 称，AWS 于 六月10日依据共同责任模型将其披露报告按“信息性”结案，并指出 allowedTools 范围限制和出口流量过滤属于客户侧控制。本次未查到 AWS 的直接答复或公开声明。

最强基线

AWS 文档说明每个会话默认可用 shell 和 file_operations，除非加以限制；allowedTools 限制模型在 InvokeHarness 期间选择工具。文档还描述了会话级 microVM 隔离，并将输入校验和提示注入防护列为客户责任。这是文档所示的配置基线，并非对所报告攻击路径的评估。
