Dynamo 论文称复用 GPU 驻留状态可将 LLM 服务恢复缩短至数秒

发生了什么变化

NVIDIA 作者于 九月 21 日发布的预印本提出 GPU Memory Service（GMS）、已初始化运行时快照和 Shadow Engine；当工作进程故障但 GPU 仍完好时，可恢复 LLM 推理副本而无需重新加载模型权重。在 vLLM 和 SGLang 的四种八 GPU 模型配置中，论文报告 Shadow Engine 恢复时间为 4.6–6.2 秒，比热重启快 12.8–29.0×。作者通过回放其生产故障轨迹估算，可挽回 79% 因恢复损失的 GPU 小时。这些是针对保留设备的进程故障报告的作者结果；设备丢失和更广泛部署表现仍待验证。

证据

  • 已展示 — 预印本提出一种恢复设计，结合已初始化引擎快照、用于持久只读模型分配的 GPU Memory Service（GMS）以及预初始化的 Shadow Engine。
  • 声称 — 在 vLLM 和 SGLang 的四种八 GPU 模型配置中，作者报告 Shadow Engine 在 4.6–6.2 秒内恢复，比热重启基线快 12.8–29.0×。
  • 声称 — 回放一条为期 18 周的生产故障轨迹后，作者估计该设计可挽回 79% 因恢复损失的 GPU 小时。
  • 已证实的局限 — 快速路径适用于保留设备的引擎进程故障；使设备失效的故障需重建模型状态，生产收益是轨迹回放估算，而非前瞻性线上测量。

最强基线

热重启基线保留了主机页缓存中的模型权重，并缓存了编译产物；作者称这比生产轨迹中的大多数恢复情形更乐观。

局限

  • 结果由作者报告，本次激活未进行独立复现。
  • 12.8–29× 数据来自八 GPU 副本以及 GPU 和模型分配仍存活时注入的引擎进程故障；设备故障需要更慢的重建路径。
  • 热重启对照使用缓存中的权重和编译结果；论文称这相较生产轨迹中的多数恢复情形偏乐观，但基准仍只适用于所测系统。
  • 79% GPU 小时收益是回放一条生产轨迹得到的估算，并非前瞻性线上部署测量。
  • 测试中 Shadow Engine 每 GPU 占用 4.3–8.1 GiB；待机并非零成本。

尚不清楚的问题

  • 本次激活未确认恢复时延、内存开销或生产轨迹收益的独立复现。

为何重要

如果这些结果能迁移到线上服务，在重建运行时状态时保留驻留模型分配，可能减少容量损失和为掩盖热重启窗口而预留的备用 GPU。对进程故障后设备和分配仍完好的集群，当前影响最大；这并未证明 GPU 或设备故障后的恢复能力。
