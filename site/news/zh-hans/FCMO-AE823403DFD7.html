LLM Inference in a Flash 报告 KV 压缩及建模的 Compute-in-Flash 收益

论文将整数运算 compute-in-flash 推理与驻留于 flash 的静态字典结合，用于存储压缩 KV 代码。在 LongBench 上，作者报告称，该组合流水线在 Llama-3.1-8B 和 Qwen-2.5-7B 上保留了 FP16 全 KV 得分的 99%，平均下降不足一个分数点，动态 KV 流量压缩近 15×。另一个针对 batch size 1 的 Llama-3.1-8B 解析模型预测：以 NPU+DDR5 全 KV 为基线，1K context 下 decode latency 降低 3.1×、能耗降低 2.7×；256K context 下分别降低 4.4× 和 6.8×。这些系统级数值是模型预测，并非物理 Compute-in-Flash 硬件测量；研究未涵盖 prefill。

真正发生了什么变化

论文将整数运算 compute-in-flash 推理与驻留于 flash 的静态字典结合，用于存储压缩 KV 代码。在 LongBench 上，作者报告称，该组合流水线在 Llama-3.1-8B 和 Qwen-2.5-7B 上保留了 FP16 全 KV 得分的 99%，平均下降不足一个分数点，动态 KV 流量压缩近 15×。另一个针对 batch size 1 的 Llama-3.1-8B 解析模型预测：以 NPU+DDR5 全 KV 为基线，1K context 下 decode latency 降低 3.1×、能耗降低 2.7×；256K context 下分别降低 4.4× 和 6.8×。这些系统级数值是模型预测，并非物理 Compute-in-Flash 硬件测量；研究未涵盖 prefill。

主张与证据

  • 声称 — 在 LongBench 上，作者报告称，其整数运算量化与字典 KV 压缩组合流水线在 Llama-3.1-8B 和 Qwen-2.5-7B 上保留了 FP16 全 KV 基线得分的 99%，平均得分下降不足一个分数点，动态 KV 流量压缩近 15×。
  • 声称 — 对于 batch size 1 的 Llama-3.1-8B，论文的解析系统模型预测：在 1K context 下，decode latency 降低 3.1×、能耗降低 2.7×；在 256K context 下，latency 降低 4.4×、能耗降低 6.8×。这是相对于 NPU+DDR5 全 KV 基线的 S2 配置模型值，并非物理硬件测量。

最强基线

LongBench 将组合方法与 FP16 全 KV cache 比较。系统模型中的 S2 配置与 B1 比较；B1 是 NPU+DDR5 DRAM FP16 基线，每个 decode step 都传输完整 KV cache。B2 和 S1 是其他建模消融配置。

最重要的限制

  • LongBench 和 KV 压缩结果由作者报告，尚未独立复现。
  • Latency 和能耗提升是解析预测，并非物理 Compute-in-Flash 硬件测量。
  • 系统模型仅涵盖 decode；论文明确将高效映射 prefill 留作未来工作。
  • 模型假设存储两份 Value 字典，一份转置、一份未转置，以支持 pursuit 和 attention。
  • 系统级预测仅针对 Llama-3.1-8B、batch size 1 和建模的 1K/64K/256K context；向其他模型、硬件、并发量和服务负载的迁移性未知。

仍然未知的部分

  • LongBench 准确率和 KV 流量压缩结果尚未经过独立复现。
  • 预测的 latency 和能耗节省尚未在物理 Compute-in-Flash 硬件上验证；研究也未对 prefill 建模。

FCMO 视角

长上下文 decode 可能受限于 KV 状态在内存与计算单元之间的传输。论文报告称，动态 KV 流量大幅降低而 LongBench 得分变化较小，随后建模了 Compute-in-Flash 设计可能带来的 decode 收益。该收益依赖设备带宽、字典放置和字典副本数量等假设，并未证明物理设备性能或 prefill 效率。
