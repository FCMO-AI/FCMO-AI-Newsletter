Groq 3 LPX 达到全面生产里程碑，第三方测得长上下文解码约 3.4k tok/s

NVIDIA 宣布 Groq 3 LPX 已全面投入生产，并披露该机架级 LPU 系统的首个第三方基准。Artificial Analysis 在 NVIDIA 托管的私有 LPX 端点上运行 Gemma 4 31B：输入上下文为 100K 时，中位输出速度为每秒 3,431 个按 OpenAI 标准化的 token；输入为 10K 时为每秒 3,382 个 token。NVIDIA 将 LPX 定位为 Vera Rubin NVL72 的低延迟补充，面向解码密集型智能体推理，采用由编译器确定性调度的通信以及以 SRAM 为主的机架级执行。

真正发生了什么变化

NVIDIA 宣布 Groq 3 LPX 已全面投入生产，并披露该机架级 LPU 系统的首个第三方基准。Artificial Analysis 在 NVIDIA 托管的私有 LPX 端点上运行 Gemma 4 31B：输入上下文为 100K 时，中位输出速度为每秒 3,431 个按 OpenAI 标准化的 token；输入为 10K 时为每秒 3,382 个 token。NVIDIA 将 LPX 定位为 Vera Rubin NVL72 的低延迟补充，面向解码密集型智能体推理，采用由编译器确定性调度的通信以及以 SRAM 为主的机架级执行。

主张与证据

  • 已证实 — Artificial Analysis 在由 NVIDIA 托管的 Groq 3 LPX 系统上运行 Gemma 4 31B，测得 100K 上下文下输出速度中位数为每秒 3,431 个 token，10K 下为每秒 3,382 个。
  • 已证实 — 所测得的输出速度描述的是首个 token 之后的生成过程，而非完整的端到端响应延迟。
  • 声称 — NVIDIA 表示 Groq 3 LPX 已全面量产，Nebius 是首家采用的云厂商，面向早期客户的批量出货预计在本季度稍晚进行。
  • 声称 — NVIDIA 记录了一个包含 256 个 LPU、聚合 128 GB SRAM，并由编译器确定性调度执行与通信的机架，作为 LPX 低延迟设计的核心要素。
  • 推断 — 现有证据足以确立在受测场景下异常高的单流解码速度，但不足以确立更优的成本、能效、多租户吞吐或完整的智能体任务耗时。

最强基线

在同样的 10K/100K 上下文方法下，Artificial Analysis 对公开 Gemma 4 31B 服务端点的测量提供了最具可比性的速度基线；NVIDIA 的技术文章显示，测试当时最快的公开端点在 100K 下为每秒 870 个输出 token，10K 下为 1,402 个。

最重要的限制

  • Artificial Analysis 测试的是托管在 NVIDIA 数据中心的私有端点，而非可普遍访问的生产服务。
  • 所披露的基准测试使用并发度为一的顺序请求；多租户吞吐、P95/P99 延迟以及负载下的调度器行为均未确立。
  • 输出速度是在首个 token 之后开始计量的；3.4k tok/s 这一头条数字既不是首 token 时间，也不是完整的端到端延迟。
  • 被直接测量的场景只有一个 31B 稠密模型；能否迁移到超大规模 MoE 模型、视觉语言模型与混合负载仍未验证。
  • 未找到关于机架功耗、每瓦 token 数、价格、每百万 token 成本或总拥有成本的对等公开测量。
  • NVIDIA 的 SPEED-Bench 结果以及每兆瓦吞吐与经济效益的大幅预测，均为厂商自测或建模所得，不应与 Artificial Analysis 的第三方速度测量混为一谈。
  • NVIDIA 称已全面量产，但其财报电话会议把面向早期客户的批量出货安排在本季度稍晚；广泛的公有云可用性未获验证。
  • 没有任何端到端智能体基准能证明，在计入工具调用、预填充、网络延迟与外部系统之后，原始解码速度之比会按比例转化为任务完成的实际耗时。

仍然未知的部分

  • Artificial Analysis 的结果目前还无法在公开或独立控制的 LPX 端点上被独立重跑。
  • 多租户吞吐、首 token 时间、P95/P99 延迟以及并发负载下的调度器行为均属未知。
  • 在已展示的场景中，能耗与经济效率没有获得独立测量。
  • 原始解码速度尚未转化为完整的智能体任务耗时。

FCMO 视角

如果这种长上下文交互速度能迁移到真实生产负载，专用解码硬件就可能消除多步智能体的一项关键串行延迟瓶颈，并显著提高异构 prefill/decode 服务架构的吸引力。不过目前证据尚未说明公共服务成本、能效、多租户吞吐、尾延迟或端到端智能体任务加速。
