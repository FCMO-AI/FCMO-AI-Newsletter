Agents & Memory

WikiSkill separates raw experience, persistent knowledge, and executable skills for agent skill evolution

Evidence Astrongly_supportedImpact 5/10 · Notableactive

paper · development FCMO-DF0FDE7BBB67 · verified 2026-08-29T22:03:00Z

Importance: 5/10 — Notable. Importance measures consequence if true, not evidence quality.
Notable if the central result generalizes: a persistent, auditable knowledge layer that materially improves procedural skill evolution and transfers procedures across models would affect practical long-lived agent design without requiring parameter updates. It is not yet major/field-shifting because evaluation uses five bounded benchmarks, injects active skills directly rather than solving retrieval, lacks very-long-horizon tasks and wiki pruning, and has no independent reproduction in ARB.

Google Research and Virginia Tech introduce WikiSkill, an agent-skill evolution loop that stores immutable execution traces separately from a persistent wiki of recurring patterns/rejected proposals and from executable skills. A maintainer consolidates experience into the wiki, a proposer uses that accumulated knowledge to revise skills, and validation gating accepts or rolls back changes. Across five benchmarks and five inference models, the authors report stronger results than prior skill-evolution baselines, with a direct ablation showing a 15-point average gain from giving the skill proposer persistent wiki access while withholding it from the inference agent.

Why it matters: The result gives unusually concrete evidence for a three-layer memory design in learning agents: raw episodic evidence, consolidated durable knowledge, and compact procedural artifacts should not be collapsed into one ever-growing context. It also shows that reusable procedures can transfer across model families, potentially allowing smaller or cheaper models to inherit useful workflows without parameter updates.

Technical record

Mechanism
Each evolution iteration produces immutable raw traces; a Wiki Maintainer consolidates recurring successes, failures, rejected proposal history and patterns into a persistent wiki; a Skill Proposer reads the wiki plus current traces to create or revise executable skills; validation gating accepts improvements or rolls them back. The inference agent receives the active skills but, in the best-performing configuration, does not read the wiki during rollouts.
Demonstrated result
On the Gemini-3.5-Flash ablation across LiveMath, SealQA, SpreadSheet and OfficeQA, enabling persistent wiki access for the Skill Proposer while keeping wiki access away from the Inference Agent raises average performance from 48.7% to 63.7% (+15.0 points). Cross-model tests show substantial positive transfer in several settings, including Qwen-3.6-27B-evolved skills raising Qwen-3.5-9B SpreadSheet from 24.3% without skills and 33.6% self-evolved to 50.5%.
Publisher claim
The authors conclude that persistent knowledge accumulation is critical to effective skill evolution, skill evolution complements model scaling, and procedural skills can transfer across model sizes and families.
Strongest baseline
No-skill inference plus dedicated skill-evolution baselines EvoSkill, SkillOpt and Trace2Skill; component ablations remove proposer wiki access and/or expose the inference agent to the wiki.
Regime
Five benchmarks (LiveMath, SealQA, SpreadSheet, OfficeQA, ALFWorld) and five inference models spanning Qwen-3.5-4B, Qwen-3.5-9B, Qwen-3.6-27B, Gemma-4-31B and Gemini-3.5-Flash. Active skills are fully injected into the system prompt rather than dynamically retrieved.
Implementation
Fresh primary preprint; ARB has not yet verified an official implementation or independent reproduction.
Compute / cost
The framework adds separate maintainer/proposer optimization calls and validation runs. ARB has not yet normalized gains by optimizer API calls, tokens, latency or dollar cost versus baselines.
Novelty
Makes accumulated agent learning explicitly three-tiered: immutable experience, consolidated knowledge with negative/rejected history, and compact executable procedure; the consolidation layer is used to improve future skill proposals rather than exposed directly to task execution.
Reproducibility
The paper provides detailed prompts, baseline descriptions and optimizer-call analysis in appendices, but independent reproduction is not yet recorded.

Evidence claims

  • DEMONSTRATED — Persistent wiki access for the Skill Proposer raises the reported four-benchmark Gemini-3.5-Flash average from 48.7% to 63.7% when the Inference Agent itself lacks wiki access.
  • DEMONSTRATED — Evolved skills can transfer across model scales and families and sometimes outperform self-evolved skills.
  • SPECULATIVE — Separating raw experience, consolidated knowledge and executable skills is a generally superior memory architecture for long-lived agents.

Limitations / contrary evidence

  • Active skills are directly injected into the inference-agent prompt, so retrieval and triggering failures are excluded rather than solved.
  • Validation gating rejects neutral changes that might enable later gains.
  • The persistent wiki has no automated pruning mechanism, leaving scaling behavior unresolved.
  • The benchmark suite does not test hundreds-of-actions or multi-hour tasks.
  • Optimizer-call/token/cost normalization against competing skill-evolution methods has not yet been audited by ARB.
  • No independent reproduction is present in the canonical record.
  • Transfer is not uniformly positive: Qwen-3.5-4B-evolved skills reduce Gemini-3.5-Flash SpreadSheet performance from 50.5% with no skill to 18.1%, showing that procedural knowledge can encode source-model-specific workarounds and actively harm stronger targets.
  • Giving the Inference Agent direct wiki access during skill evolution reduces the reported four-benchmark average from 63.7% to 60.9%, suggesting more accessible memory is not automatically better.
