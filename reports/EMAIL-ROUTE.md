# Email route decision — L26

Decision date: 2026-10-05. **Use self-hosted Listmonk 6.2.0 with Amazon SES SMTP on shared provider IPs.** Keep the newspaper on Pages. A small loopback gateway owns consent, authenticated dispatch and the durable dispatch journal; Listmonk owns confirmation, audience selection, recipient-specific unsubscribe, and suppression. SMTP transport is replaceable, but another provider is not silently enabled by this implementation.

This is an engineering recommendation, not a measured inbox-placement victory. There is no FCMO sending history or seed-mailbox evidence yet. Production activation requires authentication, feedback, provider approval and real Gmail/Outlook/Yahoo mailbox checks. Public content does not make subscriber addresses public; ZDR was not a selection criterion.

## Workload and economics

Assume one Diario per day, 30 days/month, each reader choosing a language: 0 / 100 / 1,000 / 10,000 subscribers means 0 / 3,000 / 30,000 / 300,000 recipient messages. Three language lists partition readers; they do not triple that estimate. Confirmations, retries and Letters would add traffic. Taxes, the existing host, DNS/domain registration, backup storage and operator time are additional costs.

SES à-la-carte sending is $0.10/1,000: **$0 / $0.30 / $3 / $30 per month**, plus message data. At a modeled 50 KB/message, 300,000 messages add about 15 GB × $0.12 = $1.80. New accounts may default to Essentials at $0.16/1,000, making the same sends $48 before data; explicitly select à-la-carte rather than assuming the older price. These are calculations from published rates, not an account quote. [AWS SES pricing](https://aws.amazon.com/ses/pricing/).

## Compliance and deliverability gates

For CAN-SPAM, use truthful sender/subject information, a valid public postal address, and an easy working opt-out; preserve suppression and honor removal well within the ten-business-day ceiling. Confirmation mail also has an unsubscribe link and receives the postal address from private runtime configuration. [FTC compliance guide](https://www.ftc.gov/business-guidance/resources/can-spam-act-compliance-guide-business).

For Mexican LFPDPPP, provide the responsible person's identity, actual domicile, purposes, ARCO/withdrawal contact, retention and processor/transfer disclosures before collection. A checkbox is not a substitute for the complete notice. Use the current 2025 law rather than an assumed old INAI regime. [Current LFPDPPP](https://www.diputados.gob.mx/LeyesBiblio/pdf/LFPDPPP.pdf).

For GDPR where applicable, consent must be demonstrable and withdrawable; processor terms, transfer safeguards and data rights must be arranged. Double opt-in helps evidence control of the address, but does not itself prove every legal obligation. [GDPR Articles 7, 13, 28 and Chapter V](https://eur-lex.europa.eu/eli/reg/2016/679/oj).

At bulk scale, authenticate SPF/DKIM and DMARC, provide RFC 8058 one-click unsubscribe and visible body opt-out, warm volume gradually, and monitor complaints. Provider acceptance and campaign `finished` are not inbox-placement evidence. [Gmail sender requirements](https://support.google.com/mail/answer/81126).

## Fit, countercase and activation boundary

Listmonk's [double-opt-in concepts](https://listmonk.app/docs/concepts/), [campaign API](https://listmonk.app/docs/apis/campaigns/) and [subscriber API](https://listmonk.app/docs/apis/subscribers/) match the source-controlled native editions. The workflow still takes only live-verified, hash-bound inputs after LKG promotion. The host independently re-reads public LKG, rechecks the live candidate and renders the same selected canonical IDs in EN/es-419/zh-Hans. Missing native prose stops all new sends; there is no runtime translation.

The strongest countercase is Ghost(Pro): roughly $105/month at 10k on monthly Publisher may cost less overall than maintaining a fragile self-hosted stack. It remains the fallback if the host administrator cannot enable reliable rootless services, or if SES production access is denied. We choose Listmonk+SES because the server is explicitly available, the operator asked to mount email, and the daily volume makes provider cost materially relevant. We do not claim that missing host prerequisites are already solved.

Observed here: Podman is rootless but has no subordinate UID/GID ranges, and no user-systemd bus is available in this execution environment. The shipping installer fails before mutation when those prerequisites are absent. Account approval, actual sending domain, DNS, public HTTPS, the real postal address and rights contact remain external activation inputs. Offline proof is strong implementation evidence; **no live subscriber email has been sent**.
